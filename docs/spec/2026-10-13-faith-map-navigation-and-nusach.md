# Faith map navigation and a Nusach map concept

**Status:** Faith map navigation built 2026-10-13 and [verified live](../testing/2026-10-14-faith-map-navigation-live-test.md) 2026-10-14 on the separate Codex branch. A [2026-10-14 visibility pass](../testing/2026-10-14-map-visibility-live-test.md) improves regional colour and roster matching; a same-day Discord research note below narrows the pin options. Dynamic map pins and actual community Nusach remain proposals. This addendum changes only the entry point and exit behavior described in [v12](v12-community-map-view.md) §2.5 and §6: the bottom-right community toggle becomes a fourth Faith-family map button, and its close actions return to Faiths. It does not supersede v12's regional paint or community roster.

**2026-10-14 entry-point revision:** The own-community strip described below was retired in favor of a [My Realm > Domain overview](../implementation/kehillah-domain-overview.md). The Faith-family button remains the map and roster entry point. This revision supersedes only the strip's return-to-Faiths behavior below.

## Faith-family button

The existing additive scripted widget now sits beside Faiths, Holy Orders, and Clerical Regions above the map banner. It is available in those three vanilla modes and in Jewish Communities when the player has at least one mirrored community. The community icon uses the same round 35-pixel form and selected glow as Faiths' own sub-buttons. Opening still paints the map and opens the roster; the toggle, roster close button, and own-community strip all return to Faiths.

CK3 1.20.1's `gui/shared/mapmodes.gui` shows the three Faith-family map buttons through `faith_mini_map_mode`. The vanilla strip vanishes in any custom map mode, and its header has no custom-mode text branch. Two extra additive scripted widgets fill those gaps only while Jewish Communities is selected: a new instance of the vanilla Faith-family button type and a map header label. No vanilla GUI file is copied into the mod.

## Clerical Regions as a visual reference

The screenshot Daniel supplied suggests a legible combination: softly colored regions, large names at distant zoom, and precise community markers. Our existing `kehillah_communities_map` already paints the tagged minhag geography, then highlights the single host barony of each Kehillah. Its roster and hover text name those communities.

The installed 1.20.1 `clerical_regions` map mode is wired to `color_mode = clerical_regions`, `large_map_names = clerical_regions`, and `selection = clerical_regions`. Those values read CK3's actual clerical-region entities; substituting them would paint and label Christian church jurisdictions rather than Jewish practice. The reusable part is the presentation idea and the Faith-family navigation, not the underlying region data.

**Proposed next visual pass:** keep the existing minhag tint and community barony overlay; make community locations unmistakable at useful zoom levels, then investigate custom regional names at far zoom. Do not label the present static geographic `kehillah_minhag` flags as each community's actual *nusach*: those flags describe a customary area, while a liturgical rite can move with a community and can coexist with others in one city. If explicit community rites from [v25](v25-by-god-alone-adaptation-proposals.md) §6 are approved and built, show both the local region and that community's rite in the marker or hover. Prototype any large on-map names without using CK3's hardwired clerical-region names.

## Visibility pass — 2026-10-14

The map now uses more distinct colours for its 15 geographic minhag areas. The community roster puts a matching colour swatch beside every populated region and super-region. Hover text labels the area as a **customary region**, and the roster explains that the area tint is not an individual community's prayer rite. The existing bright Standing-band host barony still marks each Kehillah, preserving v12's one-barony overlay.

A pin prototype copied CK3 1.20.1's `province_map_icon` into the mod's `gui/map_icon_layer.gui`. In a separate live game, a diagnostic pin appeared in the close-up Details map and its tooltip resolved the Worms community correctly. It did not render in the custom Jewish Communities map mode at the paper-map zooms where a pin is needed, even when its visibility condition was unconditional. The copied vanilla file was removed; shipping a 6,000-line GUI override for a pin absent from this map would be a poor trade. Custom map modes expose colour and hover scripting, while Clerical Regions' large labels and icons read hardwired church entities. Static map objects for the 1066 starts would also become misleading after community movement or dissolution.

## Map pin research — 2026-10-14

After the live prototype, the CK3 Mod Co-op's GUI modding discussion provided an explanation worth testing against the installed game. [A modder reported](https://discord.com/channels/735413460439007241/825742717895704616/1482384234621440082) adding conditional icons to an existing province icon via `ProvinceIcon.GetHolding.GetProvince`, but said they inherit the parent icon's display rules. In the following replies, another modder described new map icon sources as requiring a [vanilla icon source](https://discord.com/channels/735413460439007241/825742717895704616/1482385209008717835), naming [contracts and situations](https://discord.com/channels/735413460439007241/825742717895704616/1482385319113265275) as the two practical workarounds. This is modder experience, not an engine specification; it is consistent with our `province_map_icon` appearing only in Details view.

Neither workaround is a drop-in community marker. [A situation experiment](https://discord.com/channels/735413460439007241/825742717895704616/1481662852954722404) reportedly needed a separate situation for each movable icon, and [the discussion](https://discord.com/channels/735413460439007241/825742717895704616/1481332887348580513) notes that involved situations create bottom-right UI entries. [A contract experiment](https://discord.com/channels/735413460439007241/735413461403566119/1398689121769361553) put dummy task contracts on the map through a debug control, but [their author noted](https://discord.com/channels/735413460439007241/735413461403566119/1398689392813539329) that fake contracts count toward adventurers' available contracts. The installed CK3 1.20.1 `gui/map_icon_layer.gui` does contain `situation_map_pin_widget`, so the situation route is concrete, but a network of fake situations or contracts would need a side-effect and zoom test before consideration for Kehillah.

The current design choice is to keep the honest regional tint, Standing-coloured host baronies, hover, and roster navigation. A later pin prototype should first demonstrate a community marker at strategic zoom with multiple simultaneous communities and no unrelated situation or contract UI effects. Do not add fake gameplay objects solely to claim this visual feature is complete.
