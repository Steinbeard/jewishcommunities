# V32: Exceptional sefarim as works made during play

**Status: PROPOSAL, NOT IMPLEMENTED — 2026-10-12.** Requested after Daniel saw
`kehillah_book.0007` say a book had arrived, although the library did not gain a work.
This would supersede V13's fixed-catalog-only assumption for *new* works and the
ordinary-artifact / universal-copy parts of the 2026-09-09 Write a Book design in
ROADMAP. It builds on the current V13 library and V24 rabbi loop. ROADMAP remains
authoritative for what has shipped.

## The current mismatch

`kehillah_write_book_decision` opens the seven-event `kehillah_book.0001`–`.0007`
chain. Every completion grants the author's community Greatness and the author
Piety/Prestige. With EP1, it also creates a **personal inventory artifact** owned
by the author. The later `kehillah_book_send_copies_effect` sends `.0007` to the
leaders of *every other registered community*. That recipient gets minor Piety
and Learning lifestyle XP. No copy is created and `kehillah_library_works` is
never changed. The 2026-10-12 wording fix calls this news rather than a book on
the shelves; it does not change the mechanics.

The library panel reads `kehillah_library_works`, a list of work flags on the
community title. Study, travel, mastery, donation and the panel currently have
explicit cases for the existing fixed catalog. Creating a new artifact does not
automatically create a library entry. A new named work needs an ID and support
in those consumers; a text-only event cannot supply it.

## Intended player experience

1. **Ordinary authorship** remains scholarship and news. Writing a commentary,
   legal treatise or poetry collection can improve the author and community and
   prompt discussion elsewhere. It does not promise a library copy. On this
   proposal's implementation, ordinary works also stop creating generic personal
   book artifacts. Keep their current quality and reward choices, but reserve
   persistent book objects for exceptional works.
2. **An exceptional possibility is discovered, not chosen from a catalog.** A
   rabbi whose learning and experience approach a particular work's conditions
   sees one contextual ambition with a readable checklist: what he has done and
   what still remains. Do not expose a menu of all possible famous books. One
   scholar can have at most one active ambition; the eligible subject should
   follow his strongest scholarship and life experience.
3. **The author writes through play.** Study, Bet Din rulings, teaching, travel
   and the relevant rabbinic track satisfy the checklist. When ready, the normal
   Write a Book chain can culminate in the exceptional work if the chosen genre
   and quality qualify. An ordinary completion is still possible if the final
   work falls short; a rare book is not guaranteed by opening the decision.
4. **A successful work has identity.** It has a stable, named world-work ID, a
   creator, date and origin community. The origin library receives its first
   copy immediately and visibly. Other libraries acquire copies through an
   explicit transmission or copying mechanism, not from merely hearing news.
   Study and travel read those copies from the same library system as older
   works. The author can receive a special artifact if EP1 is present, but the
   library entry must work without DLC.
5. **Uniqueness belongs to the work.** One world-work ID can be created once in
   a campaign. Characters other than the historical author may fulfil its
   archetype. The work's name is stable; the recorded author and origin are
   generated by the actual campaign. Existing historical works remain in the
   starting/acquisition catalog and cannot be authored again.

### First example: *Moreh Nevuchim*

A Rambam-like philosopher-rabbi could discover the prospect after becoming
distinguished in Hashkafa and encountering a conflict between philosophical
argument and religious teaching. Reaching authorship should additionally need
very high Hashkafa mastery, strong Learning, study of earlier philosophical
works, and a sustained writing project. The thresholds and exact qualifying
experiences need balancing against real play; mere possession of the Rabbi trait
or one high stat must not create it. Its first copy enters the author's
community library, where another character can study it. Historical Maimonides
may qualify through play, but his identity is not a hardcoded requirement.

## Implementation route and gates

- **Spike the data model first.** The existing flag-list panel can show a named
  work with a predeclared flag, but dynamically localizing its actual author,
  date and origin from that flag needs a verified scope path. Also verify a
  reliable one-per-world creation guard and how donated/copied entries retain
  attribution. Do this in one vertical slice before adding more titles.
- **Prototype one work end to end:** eligibility preview; visible progress;
  successful writing; one unique creation; origin library row; study and travel;
  one copied second library; save/reload; and an EP1-off run. Add console-only
  probes for the near-eligible and completed states.
- **Keep catalog plumbing explicit.** The current library panel is generic,
  but study selection, work IDs, scripted GUI studied markers, and several
  acquisition paths enumerate works. The first work must be wired into those
  paths before a notification calls it a library book.
- **Balance before expansion.** Exceptional works should be rare across the
  entire map, emerge from distinctive scholar histories, and have effects
  proportionate to the rarity. Later candidates can cover commentary,
  responsa and poetry, each with different lived prerequisites.

This proposal does **not** assert that CK3 can create unlimited new work IDs or
GUI rows with fully dynamic names. The finite named archetypes plus dynamic
authorship approach fits the existing flag list; author display and circulation
still need the spike and a live test.
