# Live test log — 2026-10-01: CK3 1.20 "Crozier" port validation

**Status: PASS on all five checks.** No crash, no hang, no Game Over, and no new error.log lines
from the mod's religion, rite, government, law or succession code. Port details:
[ck3-1.20-crozier-port.md](../implementation/ck3-1.20-crozier-port.md).

## Method

- **Game:** CK3 1.20.0.2, started by the user from the Paradox launcher with a playset holding
  only Jewish Communities.
- **Launch mode:** the custom "Debug + Develop" launcher entry (`-debug_mode -develop`).
  `debug.log` confirms `Jewish Communities|mod/jewishcommunities.mod|Enabled`.
- **Run:** a Sonnet subagent drove the user's already-running game. The user started a fresh
  Worms 1066 game as Isaac HaLevi. The agent used `run <file>.txt` probes, console `event`
  commands, and a few downscaled screenshots.
- **Launch caveat (new on 1.20):** launching `binaries\ck3.exe` directly with the mod in
  `dlc_load.json`, the method all earlier logs used, loaded **no** mods on 1.20; the `Mod:` list
  was empty. An earlier attempt the same night tested vanilla because of this, and was stopped.
  Until a direct-launch method is found, live tests must attach to a launcher-started game.

## Probe-writing notes

- `rite = rite:<key>` works as a live trigger, although it isn't listed in the generated
  `triggers.log`.
- `[ROOT.Char.GetName]` inside `debug_log` text doesn't resolve: it prints blank and logs a
  `pdx_data_localize.cpp` data error. Use `debug_log_scopes` to get names.
- In a probe, don't read a variable set in the same tick across `if`/`else_if` branches. The
  engine's tooltip pre-pass evaluates them before `set_variable` runs and logs spurious errors.
