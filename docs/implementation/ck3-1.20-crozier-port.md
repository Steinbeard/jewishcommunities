# CK3 1.20 "Crozier" port

**Status:** Ported in source 2026-09-30 against CK3 1.20.0.2. **Boot-tested and validated live
2026-10-01**: faith/rite, government, law, Norman Conquest founding and a full succession all
PASS. See [the live test log](../testing/2026-10-01-ck3-1.20-port-live-test-log.md). ck3-tiger
can't validate this port yet; see "Verification" below.
Supersedes the "full vanilla override" parts of
[v1-kehillah-implementation.md](v1-kehillah-implementation.md) §5 for the succession law.

## What 1.20 changed that mattered to this mod

1.20 rebuilt the religion system and the law-file format. Both broke the mod, because the mod
carried 1.19-shaped copies of vanilla objects.

| 1.20 change | Effect on this mod |
|---|---|
| Faiths moved out of `religion_types/` into `common/religion/faith_types/`. Religions now wrap their header fields in `religion_details = { }`. | `kehillah_judaism_reserved_names.txt` overrode `judaism_religion` in the old nested-faiths format. |
| New **Rite** layer under faiths (`common/religion/rite_types/`). `rabbinism` and `merkabah` are now Rites of a new faith, **`rabbinic_faith`**. The other Jewish faiths (karaism, samaritan, kabarism, haymanot, malabarism) are each a faith with a same-named main Rite. | Every `faith:rabbinism` / `faith:merkabah` reference was dangling. |
| Character history uses `rite = "…"`; vanilla uses no `religion =` lines in 1.20 history. | All 18 `religion = "rabbinism"` history lines. |
| Bookmark characters' `religion =` takes a **Rite** key. | `religion = catholic` (now a faith) on the Worms bookmark's alt character. |
| Laws are standalone top-level objects naming their group via `law_group_type`; groups moved to `common/law_groups/`. | The full-file copy of 1.19 `00_succession_laws.txt` was both stale (~3,900 lines out of date) and **no longer necessary**. |
| `is_playable_character` rewritten (`is_ruler = yes` AND domicile/landed/minister/laamp). | The mod's override was the 1.19 trigger plus one line. |
| `GOVERNMENT_TYPES` define gained `monastic_holy_order_government` and `ecclesiastical_government`. | The mod's redeclared list would have silently dropped both. |
| Trait `scholar` merged into `erudite` (see vanilla `trait_conversion.lookup`). | Four references. |
| `pool_repopulate_local_flavor` template now assigns `rite` and sets faith+rite pairs. | The mod's override was a 1.19 copy. |

## What was done

- **Religion:** regenerated `religion_types/kehillah_judaism_reserved_names.txt` from 1.20's
  `00_judaism.txt`, changing only the top-level reserved names. Added
  `faith_types/kehillah_judaism_faith_names.txt`, which holds 1.20 copies of `rabbinic_faith`,
  `karaism`, `samaritan` and `kabarism` with the mod's per-faith name layers.
  - **Design decision (conservative):** Rites can't reserve names, so the Merkabah mystics'
    names (Yishmael, Nechunya) now share `rabbinic_faith`'s list with the Tannaitic/Amoraic
    sages. Akiva was already on both lists.
- **References:** `faith:rabbinism` → `faith:rabbinic_faith` (+ `rite = rite:rabbinism` in
  `create_character`). `is_rabbinic_authority_jewish_trigger` drops its merkabah branch, since
  `faith:rabbinic_faith` covers both rites. The mod's `create_character` blocks that copy a
  scope's faith now also copy its rite, matching vanilla. This keeps a Merkabah leader's new
  community members Merkabah rather than defaulting to the main rite.
- **History / bookmark:** `religion = "rabbinism"` → `rite = "rabbinism"`; bookmark
  `catholic` → `roman_rite` (Catholicism's main rite from 1054.7.16).
- **Succession law:** deleted `common/laws/00_succession_laws.txt`. The law now lives alone in
  `common/laws/kehillah_succession_laws.txt` with `law_group_type = succession_order_laws` and
  `index = 100`. This ends v1 §5's biggest compatibility cost. The old `potential` block was
  dropped: 1.20's `_laws.info` doesn't list it, and `can_have` carries the same gate.
- **`is_playable_character`:** re-based as `OR { <vanilla 1.20 verbatim>,
  government_has_flag = government_is_kehillah }`. The Kehillah branch behaves exactly as it
  did in 1.19.
  - **Open question:** 1.20's `exists = domicile` branch may make this override unnecessary.
    Test that only after the boot passes.
- **`GOVERNMENT_TYPES`:** re-synced to the 1.20 list, with `kehillah_government` appended.
- **Pool template:** regenerated from 1.20 vanilla, re-applying only the Romaniote/Italki
  culture routing.
- **`scholar` → `erudite`** in officers, leadership scoring and Kehillah trait compatibility.
- `descriptor.mod` / README bumped to `1.20.0.2`.

## Left as-is, worth a look

- `faith = { has_doctrine = doctrine_polygamy }` in the bet din effects/events. Faith-scope
  `has_doctrine` is still valid (vanilla uses it ~450 times), but vanilla now checks polygamy
  per rite (`rite_has_doctrine`). Not changed in this pass, because those files carry unrelated
  uncommitted work.
- `name_list_radhanite`: 1.20 vanilla has `dynn_…` Cochin dynasty names that the mod's
  override lacks. It's unclear whether they're new in 1.20 or were dropped on purpose.
- `kehillah_score_scholar_desc` loc still reads "A scholar". That still fits as wording for the
  `erudite` check.
