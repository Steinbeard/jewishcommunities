## Behavior

`kehillah_communities_map` already uses `selection = holding`, so clicking a barony opens CK3's holding/county view. The inspector is a child of the **first** `holding_view` window in `window_county_view.gui` and reads the selected province's `kehillah_inspector_community` title variable. It opens automatically on a community barony in the Jewish Communities map mode. Outside that mode, a small menorah tab beside the vanilla holding tabs toggles the inspector for any ruler. The tab stays visible but disabled where the selected holding has no community; its hover explains the control and shows any recorded county history. Closing the county view clears the toggle.

In the Jewish Communities map mode, clicking a holding without a current community opens an empty-site assessment. Its overall result calls the same `kehillah_founding_site_trigger` that founding gameplay uses. Separate lines read the realm's settlement-policy triggers, county development bands (the founding minimum of 8 and urban-opportunity bands at 5/15/25), the diaspora registry for spacing/reach, county peace/faith conditions, and the top liege's existing outlook on the Jews. The outlook indicates potential violence; an exact incident chance needs a living community. A county with a Kehillah in another barony explicitly reports that blocker. The county's durable history variables supply a founding/loss/refounding summary; the authored Kairouan loss in 1057 is one example. Existing saves without V50's history seed cannot display unrecorded past events.

The existing `kehillah_map_community` variable is transient map-paint data: the other custom map modes clear it. The normal holding view therefore uses a separate persistent province link. `kehillah_cache_map_view_facts_effect`, already called at game start, on quarterly player refresh, after founding/succession, and during community-map painting, removes the old province link before resolving the current host barony and writing the new link. Dissolution clears it before destroying the title. An older save acquires the link on its next roster refresh or by the console-only `kehillah_debug.138` event. This cache records the one host barony, consistent with the map mode's occupied-barony highlight.

The inspector shows the community title, leader portrait and name, Standing, the three pillar scores/bands/trends, host realm, and a button to open its Jewish Quarter. Score hovers reuse the established breakdown tooltips. The Quarter button uses the same `ToggleGameViewData('domicile', Title.GetHolder.GetDomicile)` route as the roster.

## GUI override and maintenance

The inspector requires the `HoldingView` context. The project's library-panel test established that window-local contexts are unavailable to a separate top-level scripted widget; CK3's data-type dump classifies `HoldingView` as a `Type`, not a global. Consequently this change copies the installed CK3 1.20.1.2 `game/gui/window_county_view.gui` to `gui/window_county_view.gui` and inserts a button and child widget in `holding_view`. The vanilla file's SHA-256 on 2026-10-25 was `4E932366E397B06347D4296C05F3C4C5850E995B010EECDA7D5A3B5A7C48675C`. `localization/english/kehillah_community_inspector_l_english.yml` holds only the new labels. The vanilla BOM is retained; pre-existing trailing whitespace in the copied file was removed so `git diff --check` passes.

This is a full GUI override and can conflict with game updates or mods that replace the county view. On a CK3 update, compare the copied file against the new vanilla version, transplant the small inspector widget, run xTiger, and live-check both a Kehillah selection and an ordinary county selection. The attached inspector sits to the right of the 605-pixel county view and is 320 pixels wide; narrow resolutions need visual review alongside the existing 630-pixel roster.
