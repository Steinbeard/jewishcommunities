# Bet Din argument flow implementation

**Status: source implementation for all 114 cases, 2026-11-25; revised from Daniel's live screenshots and xTiger checked; live retest pending.** This implements the common hearing sequence proposed in [the argument and vote spec](../spec/2026-11-24-bet-din-argument-and-vote-flow.md), with the limits below. It depends on the [100-case docket integration](2026-11-23-bet-din-docket-research-integration.md).

## Live UX revision, 2026-11-25

Daniel's live test confirmed that native `show_as_tooltip` weighted outcomes render percentages, while the original scripted-value localization rendered a bare percent sign. The option preview now uses the same script values as the saved roll, names its primary skill and relevant traits, explains trait-based stress, and gives outcome text instead of an empty-effect line. Unavailable citation choices are hidden; the citation screen names available mastered works and explains when none is known. Citation chances use the same native preview pattern. The personal feedback event was removed: after the last citation, the court's ruling screen reports the player's argument, both other judges' positions, and the prevailing ruling together. Generic filler on that screen was trimmed. Party opinion reasons now combine the ruling's direction and quality into one modifier with the same summed value as before. These changes need a live reload and retest; xTiger cannot verify rendered tooltip layout or the immediate chain of event deliveries.

The original fourteen cases now use the same five-stage chain. Cases 1–3 retain two substantive positions; cases 4–14 retain three. Their existing resolution events were moved to stage four, preserving case-specific family, doctrine, economic, and fact outcomes. The amulet case still discovers its hidden truth at the opening and maps the winning argument to its original truth-sensitive ruling; dismissing the amulet still has its special stress and courtier reaction when it wins. Case-specific results now receive the combined three-judge tally. The old generic third-judge source events remain defined but are no longer called by these chains. `scripts/kehillah_upgrade_legacy_docket.py` records the one-time migration; generated panel names now cover all 114 cases.

Later live feedback led to a compact ruling layout with distinct persuasion labels, a six-way fact-sensitive result in the private-judge case, and a progress bar whose tooltip is titled “Strength of Bet Din Rulings.” The bar itself no longer prints the score. `kehillah_bet_din_close_docket_effect` no longer zeroes the activity score and case count before the conclusion screen; the next session's opening still resets both. The option tooltip now links the main CK3 skill and shows the base and skill contribution rule, plus only active trait bonuses. This is a concise scripted breakdown rather than the GUI-only `GetScriptValueBreakdown` widget.

## What changed

For each of cases 15–114, all three judges now choose among the same three case-specific positions. The source and scholar/steward combination buttons no longer appear on the opening screen. An argument choice records the position and its chance from Diplomacy, Learning or Stewardship and relevant traits. The cited option no longer acts as a separate ruling. A citation screen then offers no book, the highest-standing mastered work on the case's Mishnah order, and a distinct low-standing work when the judge knows one. A banned or anathematized work remains available with the existing cherem warning and consequence. The source changes that judge's final argument chance and, on success, the vote's weight. The roll is reported together with the panel's decision.

After three arguments, the panel combines successful argument weights by position. Equal weight favors the position with more judges, then the presiding judge's position. The winning position, not the first judge's proposal, drives the existing case outcome, party response and pillar costs. A fact-sensitive bonus rewards a well-supported ruling for either side; the inquiry position loses a small amount for delay. The ruling screen names each judge's position, says whether it persuaded the court, and gives the prevailing ruling. Percentages and internal weights remain in the calculation, not the ruling prose. The activity log names successful and failed citations. Successful sources count toward work standing only on a good or great case result, for the judge who cited them. Per-case vote state is cleared before the next draw.

The conference summary now shows current standing, cases decided and the thresholds for adequate, strong and landmark results. This uses the vanilla hunt widget pattern. It labels an untouched docket as awaiting its first ruling and does not claim a final success probability.

The shared logic lives in `common/scripted_effects/kehillah_din_argument_effects.txt` and `common/script_values/kehillah_din_argument_values.txt`. `scripts/kehillah_rewrite_docket_arguments.py` moves authored event files to the common five-stage flow after the prose generator runs. The original event template is retained under `scripts/templates/` so regeneration does not inherit already rewritten stages. `scripts/kehillah_generate_argument_panel_loc.py` generates the case-specific position and source names used on the panel screen. The less familiar citation category now requires standing 4 or below; the source catalog generator and its generated effects agree.

## Limits and follow-up

- The first fourteen cases retain their bespoke ruling and special effects after the shared argument and citation sequence. Their unique consequences still need a live pass through representative outcomes.
- The authored choices retain their existing prose. The shared challenge mapping is currently A: Diplomacy, B: Learning, C: Stewardship. This removes gated guaranteed-success buttons but should be tuned per case after seeing live choices. Trait and stress interactions are present but not yet tailored to every premise.
- The citation categories use standing as the practical distinction. The well-established candidate is highest-standing; the obscure candidate is the newest mastered noncanonical work at standing 4 or below. They are not yet ranked by actual master count. The displayed chance uses the existing standing-based reliability, while success weight uses the current master-count-based strength.
- The progress bar, revised option tooltips and five-stage delivery have passed source and xTiger checks, not a complete in-game visual or arithmetic probe. Daniel's screenshot confirms the native preview displays numeric percentages. A user live test or Luna session should confirm that the revised citation choices and stress explanations render, displayed chance matches the roll, source names and bans render, the panel votes determine the ruling, cleanup prevents leakage between cases, and the bar updates after a completed ruling. Check `error.log` against a boot baseline.

## Verification

The source audit found one five-stage event chain, one citation screen, one panel computation and one cleanup call for each of 114 cases. Each judge has three arguments except in cases 1–3, which have two. The current xTiger run against CK3 1.21.0.3 reported the same diagnostic list as the shared checkout's pre-change baseline; no new diagnostic appeared. The hidden `kehillah_din_argument_debug.1` event reports the active argument and vote state for a scripted probe. No live test was run by Codex under the repository's Luna-only rule.
