# =====================================================================
# Community library events -- inventory actions on a held work. ADDED
# 2026-09-18 at user request ("an inventory management system... click
# a donate book option for some piety"). v13 spec section 10.
#
# ONE EVENT SO FAR: kehillah_library.0001, the donate confirmation,
# reached only from the library panel's per-row button (gui/kehillah_
# domicile_library.gui -> scripted_gui kehillah_lib_donate_work, common/
# scripted_guis/kehillah_map_view_gui.txt). It is a confirmation on
# purpose: donating is irreversible, the work leaves the community's
# library for good, and the only way back is the acquire decision's
# random draw two years later.
#
# WHICH WORK: scope:kehillah_donate_work, the flag scope the button
# passed through. Localisation cannot look a key up by flag name, so
# the description is a first_valid over the (now twenty-three, UPDATED
# 2026-09-19 same-day follow-up when the Talmud split into Sedarim and
# Hashkafa's pre-867 backfill grew the corpus -- see kehillah_scripted_
# triggers.txt's own updated header) works, each reusing the panel's own
# kehillah_lib_tt_<flag> line (title, subject, description) -- the same
# shape the acquire event uses for the same reason. Adding another work
# means one more triggered_desc here, next to its loc lines.
#
# WHERE IT GOES: a random registered community that LACKS the work
# (scope:kehillah_donate_recipient, chosen in immediate) -- the copy
# stays in the world, in a library the player can later travel to, and
# that community's leader is grateful. If every community already holds
# it, the fallback option sends it abroad for less piety
# (kehillah_donate_work_abroad_piety, common/script_values/kehillah_
# library_values.txt) -- the mitzvah is real either way, but keeping a
# reachable copy in play is worth more.
# =====================================================================
