# =====================================================================
# Kehillah decisions -- the v1 minimal set.
#
# Source of truth: docs/spec/v1-kehillah-community.md section 3 and
# section 7, question 4.
#
# The spec proposed "starting minimal (fund a Synagogue-quarter
# building, appoint each of the three officers, mediate a family
# dispute) and growing from there rather than designing the full
# decision list up front". This file follows that, with one adjustment
# worth stating plainly:
#
#   - "Fund a Synagogue-quarter building" is NOT a decision here. The
#     domicile window already is that interface -- picking a building,
#     paying for it and watching it go up. Wrapping the same action in
#     a decision would be a second, worse door onto the same room.
#   - "Appoint each of the three officers" is likewise not a decision.
#     Court positions have their own vanilla appointment UI, and that is
#     where the building gate is enforced (see
#     common/court_positions/types/kehillah_officers.txt).
#
# That leaves the decisions that genuinely have no home elsewhere:
#
#   Distribute Tzedakah                -- Gold spent, Stability gained
#   Compose a Commentary               -- Greatness
#
# (Renamed 2026-09-07 from the original Steward/Prosper/Study labels
# when the pillars themselves were renamed to Prosperity/Stability/
# Greatness -- see docs/spec/v1-kehillah-community.md section 3.)
#
# RETIRED 2026-09-07 (Wave 1 of docs/spec/v2-pillar-economy-and-lifecycle.md,
# section 8): Mediate a Dispute Between Families used to live here,
# resolving on the leader's Stewardship whenever the player chose to
# take it. It has been replaced by an ORGANIC event pair --
# events/kehillah_dispute_events.txt, on its own on_action
# (kehillah_dispute_pulse, common/on_action/kehillah_on_actions.txt) --
# rather than a decision the player summons at will. v2 spec section 3
# names this explicitly as the "organic family-dispute ruling" that
# supersedes the decision. The new version keeps the same Stewardship
# check and threshold shape (see the event file's header) but adds two
# things a decision structurally couldn't: it arrives on its own
# schedule rather than on demand, and it offers a fourth option --
# delegating the ruling to the Chief Rabbi, resolved on Learning instead
# -- which needed real disputants (picked at event immediate) to mean
# anything, not just an abstract "the community" the old decision spent
# standing against. kehillah_mediation_standing_cost (common/
# script_values/kehillah_script_values.txt) and
# kehillah_requires_stability_cost_tt (localization) went with it --
# the new event has no upfront cost, only outcomes -- and
# kehillah_mediate_dispute_decision's own localization keys
# (kehillah_mediate_dispute_decision / _desc / _tooltip / _confirm,
# kehillah_mediate_dispute_great_tt / _good_tt / _poor_tt) were removed
# from kehillah_l_english.yml in the same pass, replaced by the new
# event's own kehillah_dispute.* keys.
#
# One of these two comes straight from the spec. Distribute Tzedakah is
# pulled up from ROADMAP.md's "cheap, reinforces an existing v1 pillar"
# backlog list, which explicitly flags it as a Phase 1 candidate. That
# is a scope addition, small and deliberate: without it the Gold-to-
# standing conversion the currency design depends on has no manual
# lever at all.
#
# COST/REWARD MECHANICS REWRITTEN 2026-09-07 when Influence was retired
# in favor of the kehillah_var_stability / kehillah_var_greatness
# variables tracked on primary_title, not the character (see docs/
# implementation/v1-kehillah-implementation.md). A decision's `cost`
# block only accepts vanilla's
# fixed resource list (gold, piety, prestige, influence, ...) -- there
# is no way to make it deduct a custom variable. Anywhere a decision
# used to cost Influence, the check moved into is_valid (with a
# custom_tooltip explaining the requirement) and the deduction into the
# effect block's first line, unconditional; anywhere a decision used to
# award Influence, that became a change_variable call on whichever
# pillar the reward actually represents.
# =====================================================================


# =====================================================================
# TAKE STOCK OF THE COMMUNITY -- pure information, added 2026-09-07
#
# Answers "should I just use a debug view?" from playtest: no. Both
# pillar variables live on primary_title (see kehillah_quarterly_
# pillars_effect's "WHY THE TITLE, NOT THE CHARACTER" note) with no
# top-bar display of their own (that needs real interface/GUI work --
# see docs/implementation/v1-kehillah-implementation.md), so there was
# no in-game way to see them at all short of the console. This decision
# is the minimal fix: its own desc text, always visible on hover in the
# decision list whether or not it is ever taken, reads the live values
# straight off the title via dynamic localization
# ([ROOT.GetPrimaryTitle.Var('...').GetValue|V0], the same pattern
# vanilla uses for e.g. activity progress bars). Taking it does nothing
# mechanical -- it exists to be looked at, not clicked.
#
# UPDATED 2026-09-07: now also reads kehillah_var_prosperity, added by
# common/on_action/kehillah_on_actions.txt's kehillah_epidemic_pulse
# (v2 spec's "epidemic pulse", Wave 1 item 2). Only the localization
# text changed here.
#
# UPDATED AGAIN 2026-09-07 (Wave 2): kehillah_var_prosperity is no
# longer fed only by the epidemic drain -- it now gets the same
# baseline-convergence accrual as the other two pillars (see
# kehillah_quarterly_pillars_effect's "BASELINE CONVERGENCE" header,
# common/scripted_effects/kehillah_scripted_effects.txt). The
# desc's localization text was updated again in the same pass to stop
# describing Prosperity as reading "at or below zero" / moving "only...
# when illness passes through the quarter", which was true under Wave 1
# but is no longer an accurate description of the mechanic. The desc
# also now shows each pillar's qualitative band (Crisis/Strained/
# Healthy/Flourishing/Legendary, v2 spec section 1.1) next to its raw
# number, via the new KehillahProsperityBandName/KehillahStabilityBand
# Name/KehillahGreatnessBandName customizable_localization functions
# (common/customizable_localization/kehillah_pillar_band_custom_loc.txt)
# -- this decision's own script is unchanged; only its localization key
# grew the band-name calls.
# =====================================================================

# =====================================================================
# DISTRIBUTE TZEDAKAH -- Gold spent, Stability gained
#
# Gold into standing, plus contentment. The community's obligation to
# its poor, which is also, straightforwardly, how a communal leader
# builds standing.
#
# This is the manual counterpart to the passive Stability the quarter's
# Hekdesh and Gabbai Tzedakah generate (kehillah_quarterly_pillars_effect):
# it lets a cash-rich, standing-poor leader convert, which matters a
# great deal right after an appointment.
# =====================================================================

kehillah_distribute_tzedakah_decision = {
	picture = {
		reference = "gfx/interface/illustrations/decisions/decision_spend_money.dds"
	}

	decision_group_type = kehillah
	sort_order = 90
	ai_check_interval = 24

	is_shown = {
		government_has_flag = government_is_kehillah
	}

	is_valid = {
		is_adult = yes
		is_imprisoned = no
	}

	cost = {
		gold = kehillah_tzedakah_gold_cost
	}

	cooldown = { years = 2 }

	effect = {
		primary_title = {
			change_variable = {
				name = kehillah_var_stability
				add = kehillah_tzedakah_stability_gain
			}
		}
		add_piety = medium_piety_gain

		add_character_modifier = {
			modifier = kehillah_tzedakah_modifier
			years = 3
		}

		custom_tooltip = kehillah_distribute_tzedakah_tt
	}

	ai_potential = {
		government_has_flag = government_is_kehillah
	}

	ai_will_do = {
		base = 50

		modifier = {
			factor = 0
			gold < 100
		}
	}
}


# =====================================================================
# COMPOSE A COMMENTARY -- Greatness. Sfarim (book) tiers, Wave 3 item 1.
#
# Spec section 3: "A signature 'compose a commentary' decision can
# produce an artifact at high Learning." v2 spec section 4's output
# table replaces the old binary (ordinary / masterwork-if-Learning-16-
# and-Yeshiva) with four bands, keyed off the community's GREATNESS BAND
# via the existing kehillah_pillar_at_least_trigger (common/
# scripted_triggers/kehillah_scripted_triggers.txt) rather than a fresh
# threshold check:
#
#   Crisis/Strained -- a private teaching note. No artifact, base reward
#     only (exactly what the old "ordinary" else-branch gave).
#   Healthy -- a real commentary. THIS TIER KEEPS THE OLD MASTERWORK
#     BRANCH'S REWARD NUMBERS VERBATIM (major_piety_gain / no-DLC
#     major_prestige_gain) -- see the rarity note below for the one
#     thing that does change.
#   Flourishing -- a widely-copied responsum: bigger piety/prestige
#     (vanilla's own next rung up the same generic ladder,
#     massive_piety_gain / massive_prestige_gain) plus a new Greatness
#     kicker (kehillah_commentary_flourishing_greatness_bonus) and
#     flavor text saying the work is cited by name elsewhere.
#   Legendary -- a chronicle of the community itself: the biggest
#     reward on this ladder (monumental_piety_gain /
#     monumental_prestige_gain, kehillah_commentary_legendary_greatness_
#     bonus) and flavor text making explicit that other communities now
#     write about THIS one -- the payoff line v2 spec section 4 calls
#     for.
#
# THE PERSONAL LEARNING FLOOR IS UNCHANGED AND SEPARATE FROM THE BAND
# GATE. is_valid's learning >= 8 check is a per-CHARACTER capability
# requirement ("can this leader write anything at all"), not a
# community-standing gate -- kept as-is rather than folded into the
# band logic, because the two questions are genuinely different (a
# newly appointed but personally brilliant leader of a Crisis-band
# community can still compose a private note; a middling scholar leading
# a Flourishing community still needs Learning 8 to attempt anything).
# The old inner "learning >= 16 AND has_domicile_parameter =
# kehillah_has_yeshiva" gate is DROPPED as a separate condition for the
# Healthy tier specifically -- a deliberate simplification, not an
# oversight: the Greatness band itself already substantially captures
# "the institution and the man are both ready" (kehillah_greatness_
# baseline_value already weighs the Yeshiva's own tiers and the leader's
# Learning), so re-checking both conditions a second time inside the
# Healthy branch would just be the same fact gated twice. If a future
# playtest finds the Healthy tier triggers too easily on Learning-8
# leaders with no real institution behind them, reintroducing an inner
# check here is the fix.
#
# RARITY ENUM, CONFIRMED AGAINST LIVE VANILLA FILES, NOT ASSUMED --
# READ BEFORE CHANGING. common/artifacts/blueprints/_blueprints.info and
# 00_reforge.txt both enumerate rarity strictly as
# common < masterwork < famed < illustrious. illustrious is therefore
# the TOP of the scale, not a middle rung -- there is no rarity ABOVE
# illustrious for a hypothetical Flourishing/Legendary tier to use, which
# is exactly the possibility this task's own brief flagged as needing
# confirmation ("better rarity if the artifact system supports a tier
# above illustrious"). It does not. Given that, and given the old
# Healthy-tier branch already used illustrious (the maximum), literally
# "keeping Healthy's behavior as-is" would leave nothing above it for
# Flourishing/Legendary to reach for. The chosen resolution: redistribute
# the three non-common rarities across the three tiers that now produce
# an artifact at all -- Healthy = masterwork, Flourishing = famed,
# Legendary = illustrious -- so rarity actually climbs with the band, at
# the cost of the Healthy tier's artifact being ONE STEP LESS RARE than
# it used to be. This is the one place in this item where "keep this
# tier's behavior as-is" (the task's own suggested default) was NOT
# followed, and it is a deliberate, reasoned deviation, not an oversight
# -- flagged here and in the final report.
#
# The DLC-degradation behavior (works without Royal Court, just no
# physical artifact) is preserved at every tier, per this task's
# explicit instruction -- see the has_ep1_dlc_trigger branch repeated
# inside each of the three artifact-producing tiers below.
# =====================================================================

kehillah_compose_commentary_decision = {
	picture = {
		reference = "gfx/interface/illustrations/decisions/decision_tale.dds"
	}

	decision_group_type = kehillah
	sort_order = 95
	ai_check_interval = 60

	is_shown = {
		government_has_flag = government_is_kehillah
	}

	is_valid = {
		is_adult = yes
		is_imprisoned = no
		custom_tooltip = {
			text = kehillah_requires_learning_8_tt
			learning >= 8
		}
	}

	cost = {
		piety = kehillah_commentary_piety_cost
	}

	cooldown = { years = 10 }

	effect = {
		add_learning_lifestyle_xp = major_lifestyle_xp
		primary_title = { change_variable = { name = kehillah_var_greatness add = major_influence_gain } }
		add_prestige = medium_prestige_gain

		if = {
			limit = {
				kehillah_pillar_at_least_trigger = { PILLAR = kehillah_var_greatness THRESHOLD = kehillah_band_legendary_threshold }
			}
			# LEGENDARY -- a chronicle of the community itself.
			primary_title = { change_variable = { name = kehillah_var_greatness add = kehillah_commentary_legendary_greatness_bonus } }
			add_piety = monumental_piety_gain

			if = {
				limit = { has_ep1_dlc_trigger = yes }
				create_artifact_book_effect = {
					OWNER = root
					CREATOR = root
					SET_SUBJECT = flag:no
					SET_TOPIC = flag:no
				}
				scope:newly_created_artifact ?= {
					set_artifact_description = kehillah_commentary_artifact_desc_legendary
					set_artifact_rarity = illustrious
					set_owner = root
				}
				custom_tooltip = kehillah_compose_commentary_legendary_tt
			}
			else = {
				add_prestige = monumental_prestige_gain
				custom_tooltip = kehillah_compose_commentary_legendary_no_dlc_tt
			}
		}
		else_if = {
			limit = {
				kehillah_pillar_at_least_trigger = { PILLAR = kehillah_var_greatness THRESHOLD = kehillah_band_flourishing_threshold }
			}
			# FLOURISHING -- a widely-copied responsum, cited by name.
			primary_title = { change_variable = { name = kehillah_var_greatness add = kehillah_commentary_flourishing_greatness_bonus } }
			add_piety = massive_piety_gain

			if = {
				limit = { has_ep1_dlc_trigger = yes }
				create_artifact_book_effect = {
					OWNER = root
					CREATOR = root
					SET_SUBJECT = flag:no
					SET_TOPIC = flag:no
				}
				scope:newly_created_artifact ?= {
					set_artifact_description = kehillah_commentary_artifact_desc_flourishing
					set_artifact_rarity = famed
					set_owner = root
				}
				custom_tooltip = kehillah_compose_commentary_flourishing_tt
			}
			else = {
				add_prestige = massive_prestige_gain
				custom_tooltip = kehillah_compose_commentary_flourishing_no_dlc_tt
			}
		}
		else_if = {
			limit = {
				kehillah_pillar_at_least_trigger = { PILLAR = kehillah_var_greatness THRESHOLD = kehillah_band_healthy_threshold }
			}
			# HEALTHY -- a real commentary. Same reward numbers as the old
			# masterwork branch; see this decision's header for the one
			# thing that changed (rarity: illustrious -> masterwork).
			add_piety = major_piety_gain

			if = {
				limit = { has_ep1_dlc_trigger = yes }
				create_artifact_book_effect = {
					OWNER = root
					CREATOR = root
					SET_SUBJECT = flag:no
					SET_TOPIC = flag:no
				}
				scope:newly_created_artifact ?= {
					set_artifact_description = kehillah_commentary_artifact_desc
					set_artifact_rarity = masterwork
					set_owner = root
				}
				custom_tooltip = kehillah_compose_commentary_masterwork_tt
			}
			else = {
				add_prestige = major_prestige_gain
				custom_tooltip = kehillah_compose_commentary_masterwork_no_dlc_tt
			}
		}
		else = {
			# CRISIS/STRAINED -- a private teaching note. No artifact;
			# the unconditional base reward above (Learning XP, a little
			# Greatness, a little Prestige) is the whole reward, matching
			# what the old "ordinary" branch gave.
			custom_tooltip = kehillah_compose_commentary_ordinary_tt
		}
	}

	ai_potential = {
		government_has_flag = government_is_kehillah
	}

	ai_will_do = {
		base = 70
	}
}


# =====================================================================
# LIGHT LOAN CONTRACTS -- Prosperity. Wave 3 item 4.
#
# Full research account, targeting rationale, and why the lender is the
# TITLE rather than the character: see kehillah_script_values.txt's
# "Light loan contracts" header (common/script_values/
# kehillah_script_values.txt). Short version: this reuses the SHAPE of
# vanilla's own confirmed-working Holy Order loan mechanic (principal
# owed, a lender reference, a variable_list of debtors, a plain
# repayment decision) but under an entirely separate kehillah_loan_*
# variable namespace, so nothing here can collide with or be disrupted
# by vanilla's own loan content or another mod using the same vanilla
# system.
#
# Two decisions, not one: EXTEND (on the Kehillah leader, gated on
# Prosperity >= Healthy) and REPAY (on the borrower -- an ordinary
# landed character, not a Kehillah government, so this is NOT in the
# kehillah decision_group_type, exactly mirroring how vanilla's own
# repay_loan_decision sits in decision_group_type = major rather than
# anything Holy-Order-specific).
# =====================================================================

kehillah_extend_loan_decision = {
	picture = {
		reference = "gfx/interface/illustrations/decisions/decision_spend_money.dds"
	}

	decision_group_type = kehillah
	sort_order = 100
	ai_check_interval = 24

	is_shown = {
		government_has_flag = government_is_kehillah
		is_adult = yes
		is_imprisoned = no
	}

	is_valid = {
		custom_tooltip = {
			text = kehillah_requires_prosperity_healthy_tt
			kehillah_pillar_at_least_trigger = { PILLAR = kehillah_var_prosperity THRESHOLD = kehillah_band_healthy_threshold }
		}
		custom_tooltip = {
			text = kehillah_loan_target_exists_tt
			exists = domicile.domicile_location.county.holder
		}
		custom_tooltip = {
			text = kehillah_loan_target_tier_tt
			domicile.domicile_location.county.holder ?= {
				highest_held_title_tier <= tier_county
			}
		}
		custom_tooltip = {
			text = kehillah_loan_target_not_indebted_tt
			domicile.domicile_location.county.holder ?= {
				NOT = { exists = var:kehillah_loan_amount_owed }
				is_imprisoned = no
				is_incapable = no
			}
		}
	}

	cost = {
		gold = kehillah_loan_principal_value
	}

	cooldown = { years = 8 }

	effect = {
		primary_title = { save_scope_as = kq_title }
		domicile.domicile_location.county.holder ?= {
			save_scope_as = kehillah_loan_target
		}

		# Defense in depth: is_valid already confirmed the target exists,
		# but this guard means a bypassed/forced execution (e.g. an AI
		# path that skips is_valid) can never write loan variables onto
		# an unset scope.
		if = {
			limit = { exists = scope:kehillah_loan_target }
			scope:kehillah_loan_target = {
				add_gold = kehillah_loan_principal_value
				set_variable = {
					name = kehillah_loan_amount_owed
					value = kehillah_loan_amount_owed_value
				}
				set_variable = {
					name = kehillah_loan_lender_title
					value = scope:kq_title
				}
				set_variable = {
					name = kehillah_loan_years_elapsed
					value = 0
				}
			}

			scope:kq_title = {
				add_to_variable_list = {
					name = kehillah_loan_debtors
					target = scope:kehillah_loan_target
				}
			}
		}

		custom_tooltip = kehillah_extend_loan_tt
	}

	ai_potential = {
		always = no
	}

	ai_will_do = {
		base = 0
	}
}


kehillah_repay_loan_decision = {
	picture = {
		reference = "gfx/interface/illustrations/decisions/decision_spend_money.dds"
	}

	decision_group_type = major

	is_shown = {
		exists = var:kehillah_loan_amount_owed
	}

	is_valid_showing_failures_only = {
		is_available = yes
		gold >= var:kehillah_loan_amount_owed
	}

	effect = {
		var:kehillah_loan_lender_title ?= { save_scope_as = kehillah_lender_title }

		# Defense in depth, same reasoning as kehillah_extend_loan_
		# decision's own guard: is_shown/is_valid already confirmed the
		# loan variables exist, but this means a forced/AI execution
		# path can never try to pay an unset lender scope.
		if = {
			limit = { exists = scope:kehillah_lender_title }
			pay_short_term_gold = {
				target = scope:kehillah_lender_title.holder
				gold = var:kehillah_loan_amount_owed
			}

			scope:kehillah_lender_title = {
				kehillah_init_pillars_effect = yes
				change_variable = { name = kehillah_var_prosperity add = kehillah_loan_repayment_prosperity_reward }
				change_variable = { name = kehillah_var_greatness add = kehillah_loan_repayment_greatness_reward }
				remove_list_variable = {
					name = kehillah_loan_debtors
					target = root
				}
			}
		}

		remove_variable = kehillah_loan_amount_owed
		remove_variable = kehillah_loan_lender_title
		remove_variable = kehillah_loan_years_elapsed

		custom_tooltip = kehillah_repay_loan_tt
	}

	ai_potential = {
		always = no
	}

	ai_will_do = {
		base = 0
	}
}
