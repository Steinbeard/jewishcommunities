# =====================================================================
# Kehillah Quarter buildings.
#
# Source of truth: docs/spec/v1-kehillah-community.md section 3c, three
# pillars (Prosperity, Stability, Greatness).
#
# REWRITTEN 2026-09-06. The original version of this file mapped vanilla
# estate slots one-per-skill onto Kehillah buildings (spec section 3c's
# first table): a Learning slot became the Beit Midrash, a Diplomacy
# slot became Shtadlan's Chambers, a Martial slot became the Communal
# Watch. That was a good way to prove the domicile system could carry
# this at all -- see docs/implementation/v1-kehillah-implementation.md
# for the playtest that confirmed it does -- but it is a bad way to
# decide what a Jewish community actually contains, because it starts
# from CK3's five skills instead of from communal life. That criticism
# is in docs/iteration/v1-iteration-notes.md section 1, written before
# this rewrite.
#
# Two buildings did not survive the rewrite:
#
#   - Shtadlan's Chambers. A shtadlan was a person and a function, often
#     an informal or occasional one. He did not generally have
#     premises. The office is now ungated -- see
#     common/court_positions/types/kehillah_officers.txt.
#   - Communal Watch. The same criticism, less visibly: a reskinned
#     vanilla Martial slot with a plausible-sounding label attached.
#     Standing firm against a threat is now also ungated, for the same
#     reason the Shtadlan is -- see
#     events/kehillah_protection_events.txt.
#
# That frees exactly one internal building family (the cap is six, one
# reserved for Phase 5's Genizah -- see the Synagogue block below), which
# is what makes room for two new ones grounded in things every real
# community of this size actually needed: a Sofer's Workshop (a scribe
# is not optional -- Torah scrolls, mezuzot, tefillin, ketubot and gittin
# all require one) and a Slaughterhouse (shechita is not optional
# either). Communal Hall is renamed Hekdesh, a real institution -- poor
# relief and hospice, not a reskinned guest room -- rather than replaced.
#
# UNVERIFIED, BY DESIGN. Per this project's established norm (see
# docs/scenarios/worms-1066.md and the iteration notes), buildings below
# are period-plausible for an 11th-century Ashkenazi community but not
# individually source-checked against Worms specifically. The Mikvah in
# particular: the surviving monumental Worms mikvah dates to the 1180s,
# over a century after this scenario; a simpler one very likely existed
# earlier, since a community cannot function without one, but that is an
# inference, not a citation. Treat every building here as Isaac's traits
# were treated (docs/implementation section on character sourcing): a
# reasonable, undocumented choice, not a researched fact.
#
# Two rules carried over from the original version, both still honoured:
#
#  1. We reuse vanilla's SLOT STRUCTURE, not vanilla's modifiers. Several
#     vanilla estate buildings grant Intrigue and scheme bonuses; the
#     Kehillah design explicitly rejects scheming as a pillar (spec
#     section 2). Every modifier below is written fresh.
#
#  2. The two remaining major officers gate on BUILDINGS, not just
#     currency: no Chief Rabbi without a Beit Midrash, no Treasurer
#     without a Countinghouse. Minor communal roles (Sofer, Shochet,
#     Gabbai Tzedakah, Mikvah attendant -- see
#     common/court_positions/types/kehillah_minor_positions.txt) gate
#     the same way on their own buildings. This is what makes growing
#     the quarter and populating it with people reinforce each other
#     instead of being two separate tracks.
#
# NOTE ON PARAMETERS: per common/domiciles/buildings/_domicile_buildings.info,
# "Parameters are not inherited from previous_building and has to be
# repeated to not get lost on upgrading." Every tier therefore repeats
# its parameters. Do not tidy these away.
#
# Art is vanilla base-game estate art referenced by path -- see the
# header of common/domiciles/types/kehillah_domicile_types.txt for why.
# The generic (non-Christian, non-Islamic) temple texture is used for
# the Synagogue. Icons are the closest semantic match available in
# vanilla's domicile_building icon set; several are shared across tiers
# of the same building, matching how the original file already treated
# the Mikvah and Countinghouse.
#
# BAND GATES, added for Wave 3 item 2 (v2 spec section 8): tier N of a
# pillar-tagged building now also requires that pillar's BAND to be at
# least a given level, via can_construct (common/domiciles/buildings/
# _domicile_buildings.info: "Is the scoped owner able to construct this
# building? Supported scopes: root (Character)" -- exactly the scope
# kehillah_pillar_at_least_trigger already expects, confirmed against
# vanilla's own can_construct usage in 00_estate_buildings.txt, which
# checks root-scope triggers like "domicile ?= {...}" and
# "dynasty ?= {...}" directly, the same shape used below). Mapping,
# per this task's own suggested default: tier 1 = no requirement (a
# thin community has to be able to bootstrap at all); tier 2 = Strained;
# tier 3 = Healthy; the Synagogue's tiers 4/5 = Flourishing/Legendary
# respectively, since it is the only track with five tiers to spread
# across all five bands.
#
# NOT gated: the Mikvah (deliberately not assigned to a single pillar at
# all -- see this file's own header above) and the Slaughterhouse (not
# named in this task's building list; left as a pure Gold-cost
# progression, consistent with the Mikvah). Both are documented
# omissions, not oversights.
#
# UNCONFIRMED LIVE: whether can_construct's custom_tooltip actually
# renders as a failure reason in the domicile UI the way valid_position's
# custom_tooltip blocks are already confirmed to (this mod's existing
# court-position files use the identical custom_tooltip-inside-a-trigger
# pattern and that IS live-tested). No vanilla can_construct block in the
# installed 1.19 files was found using custom_tooltip itself (every
# vanilla example checks a plain trigger with no tooltip override), so
# this specific combination is this mod's own extrapolation from a
# generically-supported script construct, not a copied vanilla pattern --
# flagged for the next live-test pass. If it does not render, the
# fallback is identical in spirit to the live-tested "Domicile Building
# level is too low" message: the building simply appears locked with
# no custom reason, which is still correct gating, just a plainer
# tooltip.
# =====================================================================


# SECOND REWRITE, same day: internal vs. external reassigned.
#
# Per _domicile_buildings.info, "internal" is not a synonym for "minor"
# -- it specifically means "has no slot of its own; lives nested inside
# a main or external building, with no separate model in the scene."
# The first rewrite put six unrelated institutions there (Yeshiva,
# Countinghouse, Mikvah, Hekdesh, Sofer's Workshop, Slaughterhouse),
# which is mechanically fine but reads wrong: a Jewish quarter is not
# one building with five invisible upgrades bolted on, and most of
# these are not naturally part of a synagogue at all.
#
# Four families move to their own EXTERNAL slots, becoming genuinely
# separate visible structures: Yeshiva, Countinghouse, Hekdesh,
# Slaughterhouse. Two stay INTERNAL, because they plausibly are annexes
# of a synagogue building rather than freestanding institutions: the
# Mikvah (ritual baths were routinely built as part of or immediately
# adjoining a synagogue complex) and the Sofer's Workshop (a scribe's
# room off the study hall, not a separate trade premises the way a
# slaughterhouse is).
#
# This needs more external slots than the quarter started with. See
# common/domiciles/types/kehillah_domicile_types.txt and the Synagogue's
# domicile_external_slots_capacity_add progression below: six external
# families now exist (the four moved here plus Market Stalls and Craft
# Workshops), so the Synagogue's tiers now unlock external capacity up
# to 6, not the previous 4. Internal capacity drops to match: 2 families
# need at most 2 slots at once, plus 1 held in reserve for Phase 5's
# Genizah (still a real institution, still not reachable yet).
# =====================================================================


# =====================================================================
# MAIN SLOT -- THE SYNAGOGUE
#
# The community's visible growth arc, and its Greatness pillar made
# literal: a synagogue outsiders can find and name is what "other
# communities' respect" looks like as a building rather than a stat.
# Each tier unlocks internal slots (for the Mikvah and Sofer's Workshop)
# and, from tier 2 on, external slot capacity (for everything else in
# the quarter) -- so the Synagogue is what literally makes room for the
# rest of the community to build.
#
# Internal slot budget: tiers 1-5 give 1/2/2/2/3 internal slots. Two is
# exactly the number of internal building families below (Mikvah,
# Sofer's Workshop), which means both can exist from tier 2 onward. The
# third slot at tier 5 is deliberately spare -- reserved for Phase 5's
# Genizah, not reachable now.
#
# External slot budget: base 2 (kehillah_domicile_types.txt), plus +1 at
# tiers 2/3/4/5 = 6 at full growth, matching the six external building
# families that now exist (Yeshiva, Countinghouse, Hekdesh,
# Slaughterhouse, Market Stalls, Craft Workshops). A small young
# community cannot have all six institutions at once; a fully grown one
# can.
# =====================================================================

# was the same reskinned-vanilla-slot problem as Shtadlan's Chambers
# (spec section 3c mapped it from vanilla's guest-room slot). A hekdesh
# -- poor relief, care for the sick, and lodging for travelers who have
# nowhere else to stay -- is a real institution rather than a slot
# filled by an art pass. It is also the natural building for the
# communal-welfare rework docs/iteration/v1-iteration-notes.md section 2
# already flagged as wanted; the Gabbai Tzedakah this building unlocks
# is that rework's first mechanical foothold, not its finished form.
#
# Tier 2 keeps the original's "hosts travelling scholars" beat: a hekdesh
# housing a passing scholar is exactly the kind of care it existed to
# provide, not a separate guest-house function.
#
# Moved out of the internal slot system 2026-09-06: a hospice/poorhouse
# is its own building in every real community that had one, never a
# synagogue annex.
#
# EPIDEMIC/PHYSICIAN HOOK, added 2026-09-07 (v2 spec's "epidemic pulse",
# Wave 1 item 2). Both tiers now also set a vanilla domicile PARAMETER,
# camp_infection_chance_buff_N, which character_infection_chance_default_value
# (common/script_values/06_ce1_epidemics_values.txt) already reads via
# host.domicile ?= { has_domicile_parameter = camp_infection_chance_buff_N }
# to reduce a character's personal infection chance -- N=1 through 6,
# -10 through -40. This reuses an existing vanilla domicile-parameter
# hook rather than inventing a new mechanic: this mod's own
# kehillah_tzedakah_gold_cost script value already confirms
# has_domicile_parameter works against the mod's OWN kehillah_quarter
# domicile type (it checks kehillah_prominent_quarter, a parameter this
# mod defines and sets itself, exactly like these two are), so the hook
# itself is domicile-type-agnostic by construction, not a Hekdesh-
# specific assumption.
#
# OPEN VERIFICATION ITEM, not yet confirmed live: whether `host` on the
# LEFT side of that check actually resolves to the Kehillah leader for
# an ORDINARY Kehillah courtier the way it needs to. Every vanilla usage
# of camp_infection_chance_buff_N found during this task's research sits
# inside `host.domicile`, and "host" as a scope link is documented
# elsewhere in vanilla (common/scripted_triggers/
# 00_courtier_guest_management_triggers.txt's scope:host.faith/.culture,
# used for ordinary court guests/courtiers, not just camp followers)
# strongly suggesting it is a generic "this character's employer/host"
# link that should resolve for any employed courtier -- but this was
# not traced all the way to its engine-side definition, and the field's
# NAME ("camp_infection_chance_buff") reads as though it may have been
# authored with only `camp` (landless-adventurer) domiciles in mind.
# Confirm on a live load with a courtier actually infected while the
# Hekdesh exists before trusting this fully; if `host` does not resolve
# for a Kehillah courtier, this hook silently does nothing rather than
# erroring, so it will not be an obvious failure to spot.
# =====================================================================
