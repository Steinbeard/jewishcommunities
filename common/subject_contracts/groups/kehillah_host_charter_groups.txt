# =====================================================================
# The Host Charter. ADDED 2026-09-23, Phase 4 -- Host Dynamics (first
# slice: the charter mechanism itself, not the expulsion/Dhimma-pact/
# purge-threat loops ROADMAP.md's Phase 4 entry also names -- those
# remain separate, unbuilt, unscoped work).
#
# Read docs/spec/v15-host-charter.md first -- this is the mechanical
# implementation of the route docs/spec/spike-host-charter-interaction.md
# researched and live-verified across four passes. Every design choice
# below cites the spike section it came from; nothing here is a fresh
# guess.
#
# is_tributary = yes, but this is NOT tribute in the vanilla sense --
# see kehillah_host_charter_contracts.txt for why the group carries no
# tax/levy/prestige contract at all (spike Q2, section 9: payment is an
# ordinary opt-in contract, not baked into the group or the engine).
#
# tributary_can_break_free = { always = no } is Q1's answer (spike
# section 8): the community itself must never be able to simply walk
# away from its charter. This is not a placeholder "no exit" -- it is a
# deliberate design constraint from Daniel directly ("I don't think it
# makes sense for a community to be able to stop paying tribute... The
# mechanisms should be expulsion, voluntarily leaving, or maybe some
# kind of resistance"). Expulsion (v2 spec section 5.2) and voluntary
# migration (v2 spec section 5.3) are the real exit paths, both already
# named as unbuilt Phase 4 seams; resistance is raw material only so far
# (spike section 11) -- until one of those three is built, this charter
# is permanent by design, which is the intended, honest state for a v1.
#
# No map-presentation fields (should_show_as_suzerain_realm_name/_color,
# suzerain_line_type, tributary_line_type) -- deliberately silent on the
# map, per spike section 5.2 ("Skip these parameters if you don't want a
# line at all"). A Kehillah's relationship to its host is not meant to
# read as a vassal/suzerain map overlay.
#
# tributary_heir_succession / suzerain_heir_succession = yes (both
# default yes, spelled out here anyway for clarity): the charter must
# survive both the community's own succession (this mod's core mechanic)
# and the host's, for free, per spike section 5 point 4.
# =====================================================================

kehillah_host_charter = {
	is_tributary = yes

	tributary_can_break_free = {
		always = no
	}

	tributary_heir_succession = yes
	suzerain_heir_succession = yes

	contracts = {
		kehillah_charter_moneylending_rights
		kehillah_charter_quarter_rights
	}
}
