# ---------------------------------------------------------------------
# is_kehillah_title_trigger
# Scope: a landed title.
#
# The single place that answers "is this title a Jewish community?".
# UPDATED 2026-09-08 (v4 spec): Speyer and Mainz added alongside Worms.
# UPDATED 2026-09-10 (v6 spec sections 3, 6): the thirteen new
# communities added across Western Ashkenaz, Eastern Ashkenaz, Anglia and
# Provence. Every later Kehillah -- the other ~9 regions v6 spec section
# 3 explicitly defers, the Phase 2 Babylonian overlay, the Phase 3
# Sephardi one -- gets added here and nowhere else.
#
# This is checked by name rather than by a title flag because it has to
# be answerable during history execution and at game start, before any
# script has had a chance to set flags on titles.
#
# ADDED 2026-09-19 (Found a Jewish Community, common/decisions/kehillah_
# found_community_decisions.txt): a trailing is_target_in_global_variable_
# list branch, alongside the fifteen hardcoded names above rather than
# replacing them. The reasoning above for why the pre-authored sixteen
# are checked by name (answerable during history execution, before
# kehillah_registered_communities exists) is untouched and still true for
# THEM -- but a community founded mid-game by that decision has no title
# history entry to be checked during at all, and by the time any player
# could reach a decision, the registry global_variable_list already
# exists (built at on_game_start_after_lobby, common/on_action/
# kehillah_on_actions.txt) and the founding effect adds the new title to
# it in the same breath it calls change_government. Every consumer of
# this trigger -- kehillah_on_title_gain, kehillah_map_view_on_title_
# gain, the domicile naming customizable_localization -- needs to
# recognize a founded community exactly as it recognizes the original
# sixteen, so this is additive coverage, not a replacement.
#
# FIXED 2026-09-20 (live diagnosis of "founded community's buildings all
# read as locked and error.log fills with kehillah_domicile_name_vanilla_
# fallback spam"): this branch was written as is_target_in_variable_list,
# the CHARACTER/REGULAR-scope checker, but kehillah_registered_communities
# is populated with add_to_global_variable_list (kehillah_found_community_
# effects.txt, kehillah_on_actions.txt). CK3 has three separate, non-
# interchangeable variable-list namespaces -- plain, local, and global --
# each with its own matching checker (confirmed directly against the
# installed 1.19 files' own generated docs, logs/triggers.log:
# "is_target_in_global_variable_list", "is_target_in_local_variable_list"
# and "is_target_in_variable_list" are three distinct entries). Checking
# the wrong namespace doesn't error, it just always returns false -- so
# every founded community silently failed this trigger's trailing branch,
# which is why kehillah_debug.61 reported "primary title is NOT
# registered" live for a freshly founded Frankfurt community even though
# add_to_global_variable_list had definitely run. Now
# is_target_in_global_variable_list, matching the add_ call it reads back.
# ---------------------------------------------------------------------

is_kehillah_title_trigger = {
	OR = {
		this = title:d_kehillah_worms
		this = title:d_kehillah_speyer
		this = title:d_kehillah_mainz
		this = title:d_kehillah_troyes
		this = title:d_kehillah_paris
		this = title:d_kehillah_cologne
		this = title:d_kehillah_praha
		this = title:d_kehillah_vienna
		this = title:d_kehillah_narbonne
		this = title:d_kehillah_beziers
		this = title:d_kehillah_lunel
		this = title:d_kehillah_toledo
		this = title:d_kehillah_cordoba
		this = title:d_kehillah_granada
		this = title:d_kehillah_baghdad
		# London/York/Lincoln/Norwich REMOVED 2026-09-25 (v18 spec) -- they
		# no longer exist at game start; once the Norman Conquest event
		# founds them, they are dynamically-created titles recognized only
		# through the is_target_in_global_variable_list branch below, the
		# same as any other Wave-5 founded community.
		is_target_in_global_variable_list = { name = kehillah_registered_communities target = this }
	}
}

# ---------------------------------------------------------------------
# kehillah_has_known_minhag_region_trigger
# Scope: a character.
#
# ADDED 2026-09-10 (v7 spec, supersedes v6 section 4's de-jure-based
# generalization). True if this character's REAL host geography
# (capital_county -- the vanilla county their primary_title's own
# capital field points at, confirmed as a working character-scope link
# for a landless Kehillah leader by this mod's own pre-existing usage,
# common/scripted_character_templates/kehillah_pool_repopulation_patch.txt's
# root.capital_county.faith / root.capital_county calls) resolves to a
# minhag region this mod actually tags: either Anglia, checked directly
# against the kingdom/empire tier rather than a tagged variable (see
# kehillah_tag_minhag_regions_effect's own header, common/scripted_
# effects/kehillah_minhag_geography_effects.txt, for why Anglia alone is
# not duchy-tagged), or one of the other eleven regions, tagged onto the
# real de jure duchy by that same one-time effect.
#
# THE SINGLE PLACE THIS TWO-BRANCH CHECK IS WRITTEN. Every other trigger
# below that needs to know "does this character's Kehillah have a known
# region at all" calls this one rather than repeating the OR -- exactly
# the single-source-of-truth discipline v7 spec's own header insists on
# ("every consumer... reads the SAME single variable off the SAME real
# duchy").
# ---------------------------------------------------------------------

kehillah_has_known_minhag_region_trigger = {
	exists = capital_county
	OR = {
		capital_county = { empire = title:e_britannia }
		capital_county.de_jure_liege = {
			has_variable = kehillah_minhag
		}
	}
}


# ---------------------------------------------------------------------
# kehillah_shares_minhag_region_trigger = { OTHER = <character scope> }
# Scope: a character. Parameter: OTHER, another character.
#
# REWRITTEN 2026-09-10 (v7 spec, supersedes v6 section 4 item 3's de
# jure version). de_jure_liege comparison no longer works for this: as
# of this pass every Kehillah community title is FLAT (common/landed_titles/
# kehillah_landed_titles.txt's own header), so primary_title.de_jure_liege
# is simply unset for all sixteen of them -- there is no longer a
# d_kehillah_<region> duchy for two sibling communities to share.
# "Shares a minhag region" is now read off REAL geography instead:
# either both communities' host counties sit under the empire e_britannia
# (Anglia), or both their host counties' real de jure duchies carry the
# SAME kehillah_minhag flag value, set once at game start by kehillah_
# tag_minhag_regions_effect. Used by activity_kehillah_bet_din_
# conference's can_be_activity_guest (common/activities/activity_types/
# kehillah_bet_din_conference.txt), called with OTHER = scope:host, and
# by the two triggers below that build on it.
#
# kehillah_has_known_minhag_region_trigger called on both sides first, as
# an early, self-documenting guard; the two AND branches below repeat the
# has_variable/empire checks anyway (has_variable guards on both operands
# before ever comparing var:kehillah_minhag = OTHER's var:kehillah_minhag,
# matching kehillah_pillar_at_least_trigger's own guard-before-compare
# discipline elsewhere in this file) so a character with no known region
# on either side reads as "does not share" rather than erroring.
#
# var:kehillah_minhag = $OTHER$...var:kehillah_minhag -- comparing two
# variables holding flag-typed values for equality, confirmed valid CK3
# syntax (common/on_action/war_on_actions.txt's var:coronation_event_1005_
# target = root.var:coronation_event_1005_target is the general var-to-
# var-across-a-scope-chain shape; common/scripted_triggers/20_health_
# triggers.txt's scope:disease_type_for_trigger = flag:lovers_pox is the
# flag-value-comparison half), not a guess.
# ---------------------------------------------------------------------

kehillah_shares_minhag_region_trigger = {
	kehillah_has_known_minhag_region_trigger = yes
	$OTHER$ = { kehillah_has_known_minhag_region_trigger = yes }
	OR = {
		AND = {
			capital_county = { empire = title:e_britannia }
			$OTHER$.capital_county = { empire = title:e_britannia }
		}
		AND = {
			capital_county.de_jure_liege = { has_variable = kehillah_minhag }
			$OTHER$.capital_county.de_jure_liege = { has_variable = kehillah_minhag }
			capital_county.de_jure_liege.var:kehillah_minhag = $OTHER$.capital_county.de_jure_liege.var:kehillah_minhag
		}
	}
}


# ---------------------------------------------------------------------
# kehillah_is_regional_greatness_leader_trigger
# Scope: a Kehillah leader (character).
#
# REWRITTEN 2026-09-10 (v7 spec, supersedes v6 section 4 item 1's de
# jure version, for the same reason kehillah_shares_minhag_region_trigger
# above was rewritten -- there is no more d_kehillah_<region> duchy for
# any_de_jure_county to iterate). Still true under exactly the same
# condition as before: this character's community has the highest
# Greatness among every OTHER community sharing its own minhag region --
# "the greatest community gets to host the Bet Din," unchanged, only the
# membership test underneath it changed.
#
# any_in_global_list, not any_de_jure_county -- iterates global_variable_
# list kehillah_registered_communities (populated at game start, common/
# on_action/kehillah_on_actions.txt; already read the same way by
# kehillah_book_send_copies_effect, common/scripted_effects/kehillah_
# book_effects.txt), confirmed vanilla iterator for a global_variable_
# list (e.g. common/casus_belli_types/00_conquest.txt's any_in_global_
# list = { variable = fp2_struggle_ending_culture_list ... }). "this"
# inside the block is each TITLE in the list directly -- every entry is
# one of this mod's own landless Kehillah titles, so has_variable/var:
# reads apply to "this" with no .holder.primary_title indirection needed,
# and holder switches to that title's own leader when the region check
# needs a character scope.
#
# root stays fixed to the calling character throughout every nested
# scope switch below (holder = { ... }, $OTHER$ = root inside the shared
# trigger) -- the same property this mod's own header comments have
# established and relied on repeatedly elsewhere (kehillah_refresh_shum_
# bond_effect's own header, common/scripted_effects/kehillah_scripted_
# effects.txt, has the fullest account).
#
# exists = holder guards before dereferencing it, matching this file's
# own has_variable-before-compare discipline -- a Kehillah title should
# always have a holder (require_landless + appointment succession), but
# an unguarded holder read on the one title that momentarily does not is
# exactly the kind of error worth not risking for free.
#
# TIES RESOLVE IN FAVOR OF WHOEVER ASKS, unchanged from the v6 version:
# the comparison is a strict > in the OTHER direction (does any sibling
# exceed me), so a tie with another sibling still lets both ask.
# ---------------------------------------------------------------------

kehillah_is_regional_greatness_leader_trigger = {
	primary_title = {
		has_variable = kehillah_var_greatness
	}
	NOT = {
		any_in_global_list = {
			variable = kehillah_registered_communities
			NOT = { this = root.primary_title }
			has_variable = kehillah_var_greatness
			var:kehillah_var_greatness > root.primary_title.var:kehillah_var_greatness
			exists = holder
			holder = {
				kehillah_shares_minhag_region_trigger = { OTHER = root }
			}
		}
	}
}


# ---------------------------------------------------------------------
# kehillah_region_can_field_bet_din_panel_trigger
# Scope: a Kehillah leader (character).
#
# REWRITTEN 2026-09-15 at user request ("the two co-judges don't need to
# be other community leaders -- they could also be courtiers or
# adventurers, but nearby community leaders are favored. This way
# frontier communities can still call batei din"). Supersedes the
# 2026-09-10 version below, kept for record: that version required THREE
# total member communities sharing the host's minhag region (a host plus
# two co-judges, co-judges drawn only from other communities), which is
# exactly what made a frontier community -- a lone or paired outpost with
# no two neighbors of its own minhag -- permanently unable to convene at
# all, no matter how learned its own court was. Now delegates to
# kehillah_bet_din_available_co_judges_value (common/script_values/
# kehillah_script_values.txt, "BET DIN CONFERENCE" section), which sums
# the SAME three pools the co-judge select_character blocks (common/
# activities/activity_types/kehillah_bet_din_conference.txt) actually
# draw from -- other same-region community leaders, the host's own
# high-Learning Jewish courtiers, and independent Jewish rulers who are
# landless adventurers or comparably learned -- so this trigger can never
# promise a panel the select_character blocks then fail to fill.
#
# OLD VERSION (2026-09-10, v7 spec, supersedes v6 section 4 item 2's de
# jure version): any_in_global_list = { variable =
# kehillah_registered_communities count >= 3 exists = holder holder =
# { kehillah_shares_minhag_region_trigger = { OTHER = root } } } -- a
# bare regional headcount, unable to see courtiers or adventurers at all.
#
# UPDATED 2026-09-17: "the co-judge select_character blocks" above no
# longer refers to anything real -- co-judges are no longer picked in
# advance at all (THE PANEL, kehillah_bet_din_
# conference.txt's own header, has the full account of why two separate
# live tests broke that design). kehillah_bet_din_available_co_judges_
# value now counts kehillah_bet_din_eligible_judge_trigger matches
# directly, the same test can_be_activity_guest gates actual attendance
# with and kehillah_bet_din_judge_score_value ranks attendees by once the
# docket opens -- one shared definition of "who could be a co-judge"
# instead of three that had to be kept in sync by hand.
# ---------------------------------------------------------------------

kehillah_region_can_field_bet_din_panel_trigger = {
	exists = primary_title
	kehillah_bet_din_available_co_judges_value >= 2
}


# ---------------------------------------------------------------------
# kehillah_bet_din_eligible_judge_trigger
# Scope: a candidate character. $HOST$ = the character being evaluated
# against, substituted by literal text replacement (this mod's own
# established, confirmed-safe pattern for a trigger needing a caller-
# supplied scope -- kehillah_pillar_at_least_trigger's $PILLAR$/
# $THRESHOLD$ is the precedent). NOT a script value: script values do not
# support save_scope_as (confirmed the hard way -- ck3-tiger's own
# "unknown token `save_scope_as`" against an earlier draft of kehillah_
# bet_din_available_co_judges_value that tried it), so kehillah_bet_din_
# judge_score_value (common/script_values/kehillah_script_values.txt)
# reads scope:host directly rather than taking a $HOST$ of its own -- it
# is only ever called from kehillah_bet_din_open_docket_effect (common/
# scripted_effects/kehillah_bet_din_scripted_effects.txt), where scope:
# host is already provided natively by on_phase_active.
#
# ADDED 2026-09-17. Previously three separate hand-written OR branches --
# this exact same test -- existed independently in can_be_activity_guest,
# the old co-judge select_character pools (both common/activities/
# activity_types/kehillah_bet_din_conference.txt), and kehillah_bet_din_
# available_co_judges_value, all needing to agree on "who could plausibly
# be a co-judge" without any single source of truth enforcing that they
# actually did. Pulled into one trigger now that the co-judge seats no
# longer need their OWN, fourth copy of this same logic (THE PANEL,
# kehillah_bet_din_conference.txt's own header) -- an open invite just
# needs "is this candidate eligible at all," the same question can_be_
# activity_guest already answered, so co-judge eligibility and general
# guest eligibility are now the SAME question asked once, not two
# questions that happened to be worded identically in two places.
#
# THREE POPULATIONS, matching kehillah_bet_din_invite_rule_jewish_
# regional_leaders/_courtiers/_scholars/_adventurers (common/activities/
# guest_invite_rules/kehillah_bet_din_invite_rules.txt), which invite
# exactly this population and no more:
#   1. A same-region community leader (is_ruler + kehillah_shares_minhag_
#      region_trigger) -- the FAVORED population, per kehillah_bet_din_
#      judge_score_value's own scoring.
#   2. Anyone (courtier or otherwise) at or above kehillah_bet_din_
#      scholar_guest_learning_threshold Learning -- bare `learning >=`
#      here, deliberately without an is_ruler/is_courtier qualifier,
#      because that is genuinely how can_be_activity_guest already
#      allowed a learned COURTIER in (LIVE-TEST FIX, 2026-09-11, this
#      file's git history) -- narrowing it now would be a real behavior
#      change smuggled into what is otherwise a pure refactor.
#   3. A landless Jewish adventurer, learned or not.
# ---------------------------------------------------------------------

kehillah_bet_din_eligible_judge_trigger = {
	NOT = { this = $HOST$ }
	is_jewish_character_trigger = yes
	OR = {
		AND = {
			is_ruler = yes
			kehillah_shares_minhag_region_trigger = { OTHER = $HOST$ }
		}
		has_government = landless_adventurer_government
		learning >= kehillah_bet_din_scholar_guest_learning_threshold
	}
}

# kehillah_shtadlan_prevails_trigger / kehillah_watch_prevails_trigger
# Scope: a character. Parameter: THRESHOLD (the skill needed).
#
# Whether a protection incident is resolved WELL rather than merely
# survived.
#
# REWRITTEN 2026-09-06, alongside the removal of Shtadlan's Chambers and
# the Communal Watch as buildings (see
# common/domiciles/buildings/kehillah_domicile_buildings.txt and
# common/court_positions/types/kehillah_officers.txt for why). The
# original version of each trigger offered a second, easier way to clear
# the bar if the matching building's top tier existed
# (kehillah_practised_advocacy, kehillah_watch_is_organised) -- "a
# practised office genuinely helps, and does not entirely substitute for
# knowing what you are doing." With no premises behind either role
# anymore, that institutional shortcut has nothing left to hang off, so
# both triggers are now a plain personal-skill check. This is the
# correct simplification, not a loss: "person and function, not
# premises" was the whole point of ungating these roles, and a building
# quietly still discounting the skill check would have undercut that.
# ---------------------------------------------------------------------

kehillah_shtadlan_prevails_trigger = {
	diplomacy >= $THRESHOLD$
}

kehillah_watch_prevails_trigger = {
	martial >= $THRESHOLD$
}


# ---------------------------------------------------------------------
# kehillah_leader_is_rabbinic_trigger
# Scope: the Kehillah leader (character).
#
# Whether the community currently reads this leader as its rabbi rather
# than a lay elder -- see common/flavorization/kehillah_title_holders.txt
# for what this actually changes (the character's displayed rank: "Rav"
# instead of "Parnas"). Historically both were real communal leadership
# types -- see that file's header for the sourcing.
#
# ADDED 2026-09-07: kehillah_rabbi_trait (common/traits/
# kehillah_traits.txt) is now the primary, unambiguous signal -- it
# means exactly "this specific person holds recognized religious
# authority", nothing weaker. The three checks that predate it stay as
# a fallback, deliberately checked on the LEADER's own traits/skill
# rather than on whether they hold the Chief Rabbi court position: the
# ruler cannot hold their own community's court positions (those are
# for courtiers), so a leader can plausibly read as a serious scholar
# on personal reputation alone without ever having held that specific
# office -- theologian and the top two Learning education tiers are
# the same signals kehillah_officers.txt already uses to judge Chief
# Rabbi aptitude; learning >= 12 is a fallback for a self-taught or
# late-blooming scholar who never received a formal education trait.
# ---------------------------------------------------------------------

kehillah_leader_is_rabbinic_trigger = {
	OR = {
		has_trait = kehillah_rabbi_trait
		has_trait = theologian
		has_trait = education_learning_4
		has_trait = education_learning_5
		learning >= 12
	}
}


# ---------------------------------------------------------------------
# kehillah_pillar_at_least_trigger
# Scope: a character holding the Kehillah title as primary_title.
# Parameters: PILLAR (the bare pillar variable name, e.g.
# kehillah_var_prosperity), THRESHOLD (a literal number or a script
# value name, e.g. kehillah_band_healthy_threshold).
#
# v2 spec section 8, Wave 2 item 4: one shared band-check trigger for
# all three pillars, so Wave 3's band-gated building tiers/decisions/
# courtier quality read off a single mechanism rather than each
# reinventing the comparison.
#
# DESIGN DECISION: PARAMETERIZED, NOT PER-BAND-PER-PILLAR. The
# alternative the task considered was 15 explicit triggers (one per
# band per pillar, e.g. kehillah_prosperity_is_healthy_trigger). Went
# with the parameterized single trigger instead because the exact
# mechanism it depends on -- a trigger parameter substituted directly
# into a var: accessor -- is CONFIRMED, not guessed, against two live
# 1.19 vanilla precedents:
#
#   common/scripted_triggers/tgp_imperial_examination_triggers.txt:
#     has_perfect_score_trigger = {
#         has_variable = $SCORE_VAR$
#         var:$SCORE_VAR$ >= imperial_examination_perfect_score_value
#     }
#   -- called with has_perfect_score_trigger = { SCORE_VAR =
#   first_place_entrant_score } (common/activities/activity_types/
#   local_examination.txt and imperial_examination.txt), i.e. exactly
#   this mod's PILLAR = kehillah_var_prosperity pattern: a bare variable
#   NAME, no quotes, substituted textually into var:$X$ at parse time.
#
#   common/scripted_triggers/03_bp1_scripted_triggers.txt:
#     house_relation_feud_flag_trigger = {
#         exists = var:$VARIABLE$
#         var:$VARIABLE$ = flag:$FLAG$
#     }
#   -- a second, independent vanilla file doing the identical thing.
#

# ---------------------------------------------------------------------
# kehillah_has_dispute_candidates_trigger
# Scope: a character (the Kehillah leader).
#
# Guards the organic dispute-ruling event (events/kehillah_dispute_events.txt,
# v2 spec section 3, replacing the retired Mediate a Dispute decision --
# see common/decisions/kehillah_decisions.txt's header) so it cannot fire
# in a thin, early community with nobody plausible to be quarrelling.
# Requires at least two adult, unimprisoned courtiers, AND that at least
# one pair of them actually belongs to different dynasties -- two
# members of the leader's own household squabbling is a family matter,
# not the "two notable families" dispute spec section 3 describes.
#
# SYNTAX CONFIRMED AGAINST LIVE FILES: "count" as a bare filter inside
# an any_X block (common/scripted_triggers/06_ce1_epidemic_triggers.txt's
# realm_has_any_epidemic, "any_sub_realm_county = { count >= $SIZE$ ... }")
# and "prev" as a link back to the immediately enclosing scope
# (common/scripted_triggers/00_activity_triggers.txt, used throughout).
#
# JUDGEMENT CALL, NOT CONFIRMED VERBATIM: this exact nested composition
# -- iterate courtiers, then from EACH one check root's other courtiers
# for a different dynasty via root.any_courtier + prev -- was not found
# written this way in any single vanilla file. Each piece is confirmed;
# the assembly is this mod's own and should be sanity-checked on a live
# load (does the guard actually gate the event out of a one-family
# community, and let it through once a second family exists).
# ---------------------------------------------------------------------

kehillah_has_dispute_candidates_trigger = {
	any_courtier = {
		count >= 2
		is_adult = yes
		is_imprisoned = no
	}
	any_courtier = {
		is_adult = yes
		is_imprisoned = no
		# FIXED 2026-09-07 (live-test finding): the previous line here was
		# "root.any_courtier = { ... }" -- chaining any_courtier as a
		# dotted link off root, rather than opening it as its own block
		# inside a root scope change. That failed live with "Failed to
		# find a valid event target link 'any_courtier'" / "Unknown
		# trigger: root.any_courtier". any_courtier is confirmed (grep
		# against the installed 1.19 files, e.g. 00_diarch_interactions.txt)
		# to be valid ONLY as its own "any_courtier = { ... }" block, never
		# dot-chained onto another scope. root = { any_courtier = { ... } }
		# opens root as a scope first, which is the correct form.
		root = {
			any_courtier = {
				count >= 1
				is_adult = yes
				is_imprisoned = no
				NOT = { this = prev }
				NOT = { dynasty = prev.dynasty }
			}
		}
	}
}

# kehillah_leadership_gender_eligible_trigger
# Scope: a character.
#
# ADDED 2026-09-11 (v10 spec sections 3-4, live-test fix). Live test
# showed the player's own firstborn daughter as the primary Kehillah
# succession heir, and separately that nothing gates who can become
# kehillah_rabbi_trait's holder either. Per explicit user instruction --
# "It should be locked to males at game start, barring some change to
# laws and maybe religion" -- true if THIS character is eligible for
# Kehillah's core leadership roles (succession candidacy, the Chief
# Rabbi office, semicha/kehillah_rabbi_trait) under the CURRENT default:
# male, OR the single deferred-reform hook below has been set.
#
# global_var:kehillah_egalitarian_succession IS THE HOOK, NOT A FEATURE.
# Checked with exists = global_var:..., the same real idiom this file's
# own kehillah_bet_din_session_score_at_least_trigger already uses for a
# global variable that may not be set (below) -- CK3 has no separate
# "global flag" effect (checked: no set_global_flag/has_global_flag
# anywhere in the installed vanilla files), so a global_variable used
# purely for its existence, never read for a value, IS the real vanilla
# idiom for a global boolean toggle. It starts, and stays, unset for the
# entire length of this pass: v10 spec section 3.2 is explicit that
# unlocking gendered succession is future work (a law, reform, or
# decision) that this pass must NOT build -- this trigger is the one
# named place a later pass hangs that unlock off, by adding exactly one
# set_global_variable call somewhere. Until then every consumer below
# reads male-only from the same single source, so a future flip needs no
# second trigger rewrite:
#   - common/succession_appointment/kehillah_leadership.txt's
#     candidate_score (inverted: penalises NOT this trigger)
#   - common/court_positions/types/kehillah_officers.txt's Chief Rabbi
#     valid_character
#   - common/scripted_effects/kehillah_bet_din_scripted_effects.txt's
#     kehillah_bet_din_grant_rabbi_trait_effect
#   - events/kehillah_bet_din_semicha_events.txt's kehillah_bet_din_
#     semicha.0001 trigger
#
# WHY is_female = no, NOT is_male = yes. Both exist in vanilla (see
# common/succession_appointment/admin_governor.txt's own gender-law
# scoring block, "ADJUST BASED ON GENDER LAW"), functionally identical
# for any character with a defined sex -- is_female is what that same
# vanilla precedent uses, so this matches it rather than inventing a
# second equally-valid phrasing.
#
# NOT A TRUE HARD EXCLUSION EVERYWHERE IT IS USED, AND THAT IS A REAL,
# CHECKED ENGINE LIMIT, NOT AN OVERSIGHT. Checked directly against
# common/succession_appointment/_succession_appointment.info: the
# succession_appointment schema exposes exactly four keys --
# candidate_score, default_candidates, allow_children,
# allow_same_tier_candidates -- and NONE of them can disqualify a
# candidate outright; candidate_score only ranks (confirmed further by
# vanilla's own strictest precedent, admin_governor.txt's male_only_law
# branch, which does not remove female candidates either -- it multiplies
# their score by (1 - appointment_opposite_gender_penalty_value), i.e.
# 1 - 1 = 0, common/script_values/07_ep3_values.txt). So even vanilla's
# own "male only" appointment law is a score floor, not a pool filter --
# the engine simply does not expose one for this succession type. This
# trigger's succession consumer therefore applies a subtract far larger
# than any realistic positive score (see that file's own comment) rather
# than a multiply-to-zero, which is a harder lock than vanilla's own
# precedent but still cannot reach zero probability if literally every
# eligible candidate is female -- same accepted tradeoff this file's
# candidate_score already makes for wrong-faith candidates, documented
# there. The court-position and event consumers, by contrast, use
# valid_character/trigger fields that ARE real hard gates (a court
# position's valid_character can flatly bar a candidate, and an event's
# trigger can flatly refuse to fire) -- those three are genuine
# exclusions, not score adjustments.
# =====================================================================

kehillah_leadership_gender_eligible_trigger = {
	OR = {
		exists = global_var:kehillah_egalitarian_succession
		is_female = no
	}
}

# =====================================================================
# LEARN TORAH BEYOND KEHILLAH LEADERS -- ADDED 2026-09-19, same-day
# follow-up, at user request ("make this available to non-Kehilla ruler
# Jews too... Jewish unlanded adventurers can use the books of the
# kehilla where their domicile is based... Jewish rulers can use the
# library of the kehilla in their capital"). Three populations, checked
# by kehillah_study_torah_resolve_library_effect (common/scripted_
# effects/kehillah_library_effects.txt) and mirrored here as a pure
# existence check (no scope to save, since this fires from is_valid/
# is_shown/the scheme's own periodic valid re-check, not an effect
# chain):
#   1. A Kehillah leader -- UNCHANGED, their own primary_title.
#   2. A landed Jewish ruler who is NOT a Kehillah -- the registered
#      community whose domicile sits in the ruler's own capital county.
#      Landless adventurers were investigated as needing this same
#      "domicile" anchor and found NOT to have one at all in vanilla --
#      domiciles (common/domiciles/types/estate, this mod's own kehillah
#      type) are gated on holding a noble-family/landed title, never on
#      landless_adventurer_government -- so capital_province is the
#      correct anchor for is_ruler = yes specifically, not a workaround.
#   3. A landless Jewish adventurer -- the registered community whose
#      domicile sits at the adventurer's own CURRENT location instead
#      (.location, the same anchor kehillah_learn_torah_journey.0001
#      already uses for an arriving traveller, common/activities/
#      activity_types/kehillah_learn_torah_journey.txt) -- confirmed, per
#      the point above, to need a different anchor than a domicile since
#      adventurers never have one.
#
# any_in_global_list, not every_/ordered_ -- a pure existence check is all
# a TRIGGER needs (the matching EFFECT below is what actually saves the
# match); kehillah_owns_any_torah_work_trigger = { LIBRARY = this } inside
# each search confirms the matched community's OWN library still holds
# something, not merely that a community's domicile occupies the right
# location -- an empty library at the right location should not count as
# "accessible" any more than no community there at all.
#
# $CHARACTER$, NOT BARE root -- root is UNSAFE here, confirmed by ck3-tiger
# catching the identical mistake in kehillah_study_torah_resolve_library_
# effect's own first draft (common/scripted_effects/kehillah_library_
# effects.txt, its header has the full account): this trigger is called
# from the scheme's own `valid` block, where root is the SCHEME, not the
# owner (root does not change through a nested scope-opening block, per
# kehillah_bet_din_available_co_judges_value's own confirmed-safe root
# usage just above in this same file -- but that safety only holds when
# root already equals the right character at the point of a call, and here
# it sometimes does not). $CHARACTER$ substitutes literal caller-supplied
# text (root from a decision/event's own top level; scope:owner from the
# scheme's own valid block, which vanilla's own scheme files always use in
# preference to root for exactly this reason) into every reference below,
# including the ones nested inside holder = { ... }, sidestepping the
# ambiguity entirely rather than guessing which one is safe at any given
# call site.
# =====================================================================

kehillah_study_torah_has_accessible_library_trigger = {
	OR = {
		AND = {
			$CHARACTER$ = { government_has_flag = government_is_kehillah }
			kehillah_owns_any_torah_work_trigger = { LIBRARY = $CHARACTER$.primary_title }
		}
		AND = {
			NOT = { $CHARACTER$ = { government_has_flag = government_is_kehillah } }
			$CHARACTER$ = { is_ruler = yes }
			# FOUND 2026-09-23, ~990 errors/load (BLOCKERS.md): is_ruler = yes
			# alone does not guarantee capital_province exists -- every OTHER
			# Kehillah leader in the game is exactly this case, a landless
			# independent ruler with no capital province at all, and this
			# branch runs against every character the scheme's own `valid`
			# block checks. Same missing-guard idiom this mod fixes
			# everywhere else a chained scope reference can be unset.
			exists = $CHARACTER$.capital_province
			any_in_global_list = {
				variable = kehillah_registered_communities
				exists = holder
				holder = { domicile.domicile_location = $CHARACTER$.capital_province }
				kehillah_owns_any_torah_work_trigger = { LIBRARY = this }
			}
		}
		AND = {
			$CHARACTER$ = { has_government = landless_adventurer_government }
			any_in_global_list = {
				variable = kehillah_registered_communities
				exists = holder
				holder = { domicile.domicile_location = $CHARACTER$.location }
				kehillah_owns_any_torah_work_trigger = { LIBRARY = this }
			}
		}
	}
}

# THE ACTING CHIEF RABBI -- ROADMAP item S4(2), added 2026-09-26
# (Sukkot heartbeat 3).
#
# THE PROBLEM. A ruler cannot hold a court position in their own court,
# so a Kehillah leader who IS a rabbi -- which the Worms, Mainz and
# Troyes starting leaders all are, kehillah_rabbi_trait and all -- could
# not serve as their own community's Chief Rabbi. The seat sat empty and
# the community lost the Chief Rabbi's whole contribution, which reads
# as a bug rather than a choice: Rashi of Troyes leading a community
# with "no rabbi" is absurd on its face.
#
# THE SHAPE. An explicit opt-in toggle (kehillah_serve_as_rabbi_decision,
# common/decisions/kehillah_rabbi_office_decisions.txt) sets a character
# flag on the leader. Every consumer of the Chief Rabbi seat then asks
# "who is ACTING as Chief Rabbi" rather than "who holds the position".
#
# ROADMAP S4(2) requires this to go through ONE shared
# trigger/value/effect trio used at every call site, not per-site special
# cases, precisely so the next consumer added cannot forget the
# serving-leader case. The trio is:
#
#   kehillah_has_acting_chief_rabbi_trigger  -- is the seat filled at all
#   kehillah_acting_chief_rabbi_learning_value  -- the pillar contribution
#       (common/script_values/kehillah_script_values.txt)
#   kehillah_save_acting_chief_rabbi_effect  -- bind scope:kehillah_chief_rabbi
#       (common/scripted_effects/kehillah_scripted_effects.txt)
#
# THE APPOINTED RABBI ALWAYS WINS. Where both could apply, every member
# of the trio prefers the court-position holder, so there is no window in
# which a community counts two rabbis -- not even between the moment a
# rabbi is appointed and the quarterly tick that clears the now-redundant
# toggle (kehillah_clear_redundant_rabbi_toggle_effect).
# =====================================================================

# Scope: a character. True if THIS character is a Kehillah leader
# currently serving as their own community's Chief Rabbi.
kehillah_serving_as_own_rabbi_trigger = {
	has_character_flag = kehillah_serving_as_own_rabbi

	# Defensive, and the reason the appointed rabbi always wins: if a
	# real rabbi has been appointed, the leader is no longer acting in
	# the role even if the flag has not been cleaned up yet.
	NOT = { employs_court_position = chief_rabbi_kehillah_position }
}

# Scope: the Kehillah leader. True if the community has a Chief Rabbi at
# all, by either route. Replaces bare `employs_court_position =
# chief_rabbi_kehillah_position` checks at every consumer site.
kehillah_has_acting_chief_rabbi_trigger = {
	OR = {
		employs_court_position = chief_rabbi_kehillah_position
		kehillah_serving_as_own_rabbi_trigger = yes
	}
}

# Scope: the Kehillah leader. Can this leader take up the office
# themselves? Recognized rabbinic standing plus real learning -- the
# same gender hook every other Kehillah leadership role uses, so a
# single future reform unlocks all of them together rather than this one
# needing its own.
kehillah_can_serve_as_own_rabbi_trigger = {
	has_trait = kehillah_rabbi_trait
	kehillah_leadership_gender_eligible_trigger = yes
	learning >= kehillah_serve_as_rabbi_learning_threshold
}

# THE CHIEF RABBI SEARCH -- ROADMAP item S4(1), added 2026-09-26.
#
# Modelled on vanilla's own physician recruitment: the decision opens an
# event offering candidates at skill tiers and gold costs, with a
# cooldown flag (common/decisions/90_minor_decisions.txt's
# hire_physician_decision item -> events/health_events.txt's health.3001).
# See events/kehillah_rabbi_search_events.txt for the pool construction.
#
# Scope: a prospective candidate. scope:kehillah_rabbi_seeker = the
# Kehillah leader doing the searching.
#
# The conditions mirror chief_rabbi_kehillah_position's own
# valid_character/is_shown_character blocks (common/court_positions/types/
# kehillah_officers.txt) deliberately -- offering a candidate the engine
# would then refuse to appoint would be a dead end the player can't see
# into. If that position's gates change, change these with them.
# =====================================================================

kehillah_rabbi_search_candidate_trigger = {
	is_alive = yes
	is_adult = yes
	is_incapable = no
	is_imprisoned = no

	# The office rules on this congregation's law. Same reasoning as the
	# position's own valid_character faith gate.
	faith = scope:kehillah_rabbi_seeker.faith

	kehillah_leadership_gender_eligible_trigger = yes

	# A community's own leader is not for hire -- they have a community.
	# Checked through the title registry rather than "has a government",
	# so a landless scholar who happens to hold some other title is still
	# recruitable.
	NOT = {
		AND = {
			exists = primary_title
			primary_title = { is_kehillah_title_trigger = yes }
		}
	}

	# Already serving someone as their rabbi. Poaching another
	# community's sitting rabbi is a different (and more interesting)
	# feature than this one; not built here.
	NOT = { has_court_position = chief_rabbi_kehillah_position }

	# Not a claimant: same reasoning vanilla gives in
	# health_3001_physician_basic_requirements_trigger -- recruitment
	# must not become a cheap route to importing claims.
	is_claimant = no

	NOT = { this = scope:kehillah_rabbi_seeker }
}


# ---------------------------------------------------------------------
# kehillah_pillars_are_live_trigger
# Scope: a character (the Kehillah leader), matching
# kehillah_pillar_at_least_trigger above.
#
# ADDED 2026-09-26 (heartbeat 5) after a live find. "Have this
# community's opening pillars actually been written yet?"
#
# WHY THIS EXISTS. The historical communities are seeded at
# on_game_start_after_lobby with all three pillars at 0, and their REAL
# opening values are set three days later by
# kehillah_settlement_conditions.0008 -> kehillah_initialize_historical_
# pillars_from_baseline_effect. That three-day delay is deliberate and
# load-bearing (see kehillah_on_actions.txt:218-225: the snapshot must
# see .0001's nearby-community cache and .0002/.0003's committed charter
# terms rather than a bootstrap-time approximation).
#
# But CK3's 1066 start is 1066.9.15 and the first
# quarterly_playable_pulse lands on 1066.9.16 -- TWO DAYS BEFORE the
# snapshot. Measured live, not inferred: debug.log for a fresh Worms
# start shows the pulse's band seeding and
# kehillah_dissolution_watch_effect running at 1066.9.16 against
# Prosperity/Stability/Greatness all exactly 0.00, then the initialization
# logging at 1066.9.18. Consequences, all confirmed in that same log:
#   - all three bands seeded as CRISIS, applying the Crisis modifiers
#     (-20% income, -20% prestige, stress) to a leader whose community is
#     really Strained/Strained/Healthy;
#   - the dissolution countdown advanced to 1;
#   - "The Community Frays" fired on day one of a new game, and with it
#     the five-year kehillah_dissolution_warned_flag cooldown -- so a
#     GENUINE early crisis would then go unwarned, defeating S1's own
#     promise that "collapse is never a surprise".
#
# WHY NOT FIX IT BY INITIALIZING EARLIER. Because the codebase already
# decided against that, explicitly, and the reason still holds:
# kehillah_worms_developed_start_effect's header says restoring Greatness
# to 0 rather than to a real baseline is deliberate, since "computing it
# here would duplicate V20's job three days early and give two places an
# opinion about the same number." Day three stays the single authority;
# the CONSUMERS learn not to read a number that has not been written yet.
#
# FIRST ATTEMPT, AND WHY IT FAILED LIVE -- 2026-09-26, same day. This
# trigger originally read "at least one pillar is above zero", to avoid
# depending on kehillah_start_pillars_initialized_from_baseline (which is
# set only on the historical-start path). **It did not work, and the live
# test caught it where ck3-tiger could not.** The verification boot still
# logged the floor watch firing and the warning going out.
#
# The reason is ordering inside the pulse itself.
# kehillah_quarterly_pulse calls kehillah_quarterly_pillars_effect FIRST,
# whose baseline-convergence block adds (baseline - current) x
# kehillah_convergence_rate_value to each pillar. From 0, against a real
# Stability baseline of ~369 and a rate of 1/20, that is a jump to ~18.5:
# non-zero, so the old predicate passed, but still below the dissolution
# floor of 25, so the watch fired anyway. The guard was reading a number
# the same pulse had already corrupted.
#
# SO THE PREDICATE IS NOW THE MARKER, and the drift is guarded too (see
# kehillah_quarterly_pulse). The two objections to the marker are handled
# rather than dodged:
#
#   - FOUNDED COMMUNITIES and COMMUNITIES IN EXISTING SAVES have no
#     marker, and guarding on a missing marker would freeze their pillars
#     forever -- much worse than the bug. kehillah_backfill_pillars_marker_
#     effect, called at the top of the pulse before any guard, sets the
#     marker for any community whose Stability is already above zero. That
#     covers both populations on their first pulse: a founded community
#     starts at Stability 50, and a save's communities carry whatever they
#     had.
#   - IT MUST NOT BACKFILL DURING THE PRE-INIT WINDOW. It cannot: with
#     the drift guarded, an uninitialised community's Stability stays at
#     exactly 0. Verified by reading every writer -- only
#     kehillah_init_pillars_effect (0), the day-three snapshot (baseline),
#     the founding path (+50) and event-driven adds touch Stability, and
#     no historical start effect touches it at all. Mainz's +650 opening
#     Prosperity is deliberately NOT enough to trigger the backfill, which
#     is why the predicate is Stability alone rather than any pillar.
#
# Residual false negative: a live, unmarked community sitting at exactly
# 0.00 Stability would stay frozen. It needs a pre-fix save AND total
# collapse simultaneously, and resolves the moment anything nudges
# Stability.
# ---------------------------------------------------------------------
kehillah_pillars_are_live_trigger = {
	primary_title = { has_variable = kehillah_start_pillars_initialized_from_baseline }
}
