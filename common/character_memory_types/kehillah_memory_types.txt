# Kehillah character memory types.

# ADDED 2026-09-15, Bet Din case 5 ("A Cursed Amulet") -- "this event
# should create a memory for the judges," per explicit user request.
# This mod's FIRST entry in common/character_memory_types/ (confirmed
# real vanilla folder name and create_character_memory = { type = ...
# participants = { ... } } as the real calling shape -- game/events/
# activities/coronation_activity/coronation_events.txt's own
# witnessed_a_coronation_memory call, "participants = { host = scope:
# activity.activity_host }", is the precedent this follows).
#
# TWO TYPES, NOT ONE WITH A TRIGGERED DESCRIPTION. A memory's own
# `description` field is re-evaluated live, whenever a player actually
# opens that memory in the UI -- which can be years after this case
# closed, long after involved_activity has stopped resolving to
# anything (the Bet Din Conference activity itself is long since over).
# A triggered_desc reading involved_activity.var:kehillah_bet_din_
# case5_direction at THAT point would silently fail. Picking one of two
# separate, fixed-text memory types AT CREATION TIME instead (kehillah_
# bet_din_amulet_resolution_effect, common/scripted_effects/kehillah_
# bet_din_scripted_effects.txt) sidesteps the whole problem -- each
# type's own description never needs to read anything beyond its
# participants, which memory descriptions are guaranteed to still have.
#
# PARTICIPANTS ARE ROLE NAMES, READ BARE IN LOC (no memory_participant:
# or scope: prefix in the .yml text itself -- confirmed against game/
# localization/english/memories_l_english.yml's own witnessed_a_
# coronation_memory_desc, "[host.GetTitledFirstNamePossessive]"), the
# same bare-name convention this mod's own save_scope_as loc references
# already use elsewhere (events/kehillah_bet_din_events.txt's own
# [kbd_litigant_a.GetFirstName], etc.).
# =====================================================================
