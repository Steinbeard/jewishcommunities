# =====================================================================
# Kehillah character memory types.
#
# ADDED 2026-09-15, Bet Din case 5 ("A Cursed Amulet") -- "this event
# should create a memory for the judges," per explicit user request.
# This mod's FIRST entry in common/character_memory_types/ (confirmed
# real vanilla folder name and create_character_memory = { type = ...
# participants = { ... } } as the real calling shape -- game/events/
# activities/coronation_activity/coronation_events.txt's own
# witnessed_a_coronation_memory call, "participants = { host = scope:
# activity.activity_host }", is the precedent this follows).
#
# TWO TYPES, NOT ONE WITH A TRIGGERED DESCRIPTION. A memory's own
# `description` field is re-evaluated live, whenever a player actually
# opens that memory in the UI -- which can be years after this case
# closed, long after involved_activity has stopped resolving to
# anything (the Bet Din Conference activity itself is long since over).
# A triggered_desc reading involved_activity.var:kehillah_bet_din_
# case5_direction at THAT point would silently fail. Picking one of two
# separate, fixed-text memory types AT CREATION TIME instead (kehillah_
# bet_din_amulet_resolution_effect, common/scripted_effects/kehillah_
# bet_din_scripted_effects.txt) sidesteps the whole problem -- each
# type's own description never needs to read anything beyond its
# participants, which memory descriptions are guaranteed to still have.
#
# PARTICIPANTS ARE ROLE NAMES, READ BARE IN LOC (no memory_participant:
# or scope: prefix in the .yml text itself -- confirmed against game/
# localization/english/memories_l_english.yml's own witnessed_a_
# coronation_memory_desc, "[host.GetTitledFirstNamePossessive]"), the
# same bare-name convention this mod's own save_scope_as loc references
# already use elsewhere (events/kehillah_bet_din_events.txt's own
# [kbd_litigant_a.GetFirstName], etc.). A TYPE-LEVEL `participants` list
# is NOT strictly required for a description to resolve a role name --
# confirmed against the installed game's own witnessed_a_coronation_
# memory (game/common/character_memory_types/ach_memories.txt), which
# has no participants field at all despite its own desc referencing
# [host...]; the actual binding happens at the CALL site's own
# create_character_memory = { participants = { ... } }. Declared here
# anyway, on every type below, purely as documentation of what each
# type's own description expects -- matching relative_died's own
# already-declared-participants shape (game/common/character_memory_
# types/character_memories_1.txt) rather than the more minimal
# coronation example.
#
# ADDED 2026-09-15: the other five cases (1-4, 6) get the same
# treatment, one memory type each -- EXCEPT case 3 ("The Second Wife"),
# which has no litigants (a communal policy question, not one
# household's dispute -- events/kehillah_bet_din_events.txt's own header
# on case 3 explains why) and so declares no participants at all, same
# as the ach_memories.txt precedent above.
#
# GOOD RULINGS ONLY, EVERY CASE, INCLUDING THE TWO ABOVE (retrofitted
# onto kehillah_bet_din_amulet_resolution_effect in the same pass): a
# memory is now created ONLY when the case's own tally lands GREAT or
# GOOD, never POOR. This is not just flavor discipline -- kehillah_has_
# good_bet_din_memory_trigger (common/scripted_triggers/kehillah_
# scripted_triggers.txt) reads "does this character hold ANY of these
# memory types" as the actual gate for a new option in kehillah_book.
# 0002 ("Write a Book"'s own inspiration step, events/kehillah_book_
# events.txt), per explicit user request: "draw on a bet din memory of
# a good ruling to improve the quality of your book." A memory that
# existed regardless of verdict quality would make that check
# meaningless -- "I hold a Bet Din memory" would no longer imply "I
# ruled well," which is exactly the fact the book chain needs to read.
# =====================================================================
