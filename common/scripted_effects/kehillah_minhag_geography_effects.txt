# =====================================================================
# Kehillah minhag geographic tagging.
#
# ADDED 2026-09-10 (v7 spec, docs/spec/v7-minhag-geographic-tagging.md,
# sections 2 and "The full 12-region duchy/kingdom table"), superseding
# v6 spec sections 1-2's titular-duchy structure (common/landed_titles/
# kehillah_landed_titles.txt's own header has the full account of why).
#
# WHAT THIS IS. A ONE-TIME effect, run once from kehillah_on_game_start
# (common/on_action/kehillah_on_actions.txt), that sets a variable,
# kehillah_minhag, on each REAL vanilla duchy title this mod's twelve
# minhag regions cover -- value = flag:<region_id>, confirmed vanilla
# syntax for storing a flag literal in a variable (common/scripted_
# triggers/20_health_triggers.txt's save_temporary_scope_value_as { value
# = flag:$DISEASE$ }, and this mod's own house_relation_feud_flag_trigger
# precedent citation, common/scripted_triggers/kehillah_scripted_
# triggers.txt, for var:$X$ = flag:$Y$ comparisons against a stored flag).
#
# WHY A DUCHY, NOT A CHARACTER OR A KEHILLAH TITLE. This is deliberately
# geography-first, not community-first: the duchy is tagged once, at game
# start, regardless of whether any Kehillah currently exists inside it.
# Every consumer -- kehillah_shares_minhag_region_trigger, kehillah_is_
# regional_greatness_leader_trigger, kehillah_region_can_field_bet_din_
# panel_trigger (all three, common/scripted_triggers/kehillah_scripted_
# triggers.txt), and any future feature (a "your minhag" tooltip, a map
# mode, Wave 5's eventual founding-anywhere event) -- reads the SAME
# single variable off the SAME real duchy, rather than re-deriving the
# classification redundantly or maintaining a second boolean-trigger-per-
# region system alongside it. A community founded anywhere (Wave 5, not
# built yet) therefore reads its own minhag correctly the moment it
# exists, with no separate registration step and nothing to keep in sync.
#
# ANGLIA IS THE ONE EXCEPTION, DELIBERATELY NOT TAGGED HERE. Its
# territory (world_europe_west_britannia) does not overlap any of the
# other eleven regions', so every consumer trigger checks capital_county
# = { empire = title:e_britannia } directly instead of reading a
# kehillah_minhag variable for this one region -- v7 spec's own reasoning
# ("no duchy-tagging needed for this region specifically"). This keeps
# nine English duchies out of the table below for no loss of coverage.
#
# WHY DUCHY TIER, NOT VANILLA'S OWN geographical_region SYSTEM. Checked
# directly, twice, against the installed files
# (game/map_data/geographical_regions/geographical_region.txt) before
# choosing a mod-defined duchy table over reusing vanilla's own regions:
# vanilla's own groupings are too coarse for the splits this mod actually
# needs. world_europe_west_francia contains BOTH d_champagne (Western
# Ashkenaz) and d_provence (Provence) in one bucket; world_europe_west_
# germania contains BOTH the Rhineland (Western Ashkenaz) and d_bohemia/
# d_osterreich (Eastern Ashkenaz) in one bucket; world_europe_west_iberia
# contains BOTH the Christian-reconquered north (Northern Sepharad) and
# the still-Muslim south (Southern Sepharad) in one bucket. There is no
# finer tier below these in vanilla's own file for any of the three, so a
# mod-defined duchy table is required wherever a region needs a finer
# split than vanilla draws -- which is every region except Anglia, above.
#
# ?= (safe existence-checked scope switch), not = , for every title: =
# below -- matches this mod's own established idiom for a title reference
# that should not hard-fail if the tag somehow does not exist (see
# kehillah_on_game_start's own title:c_kehillah_worms ?= { ... } calls,
# common/on_action/kehillah_on_actions.txt). Every duchy tag below was
# independently confirmed present in the installed 1.19 files during this
# pass's own verification (see each region's header for the exact grep
# each was checked against); the guard is defensive, not an admission of
# doubt.
#
# HOW EACH REGION'S TABLE WAS SOURCED, only four of twelve regions (2, 3,
# 4, and the kingdom-tier check for 1) had actual Kehillah communities
# before this pass and had already had their own duchy lists checked
# against the installed files by the v6 and v7 specs directly -- those
# four are reproduced here verbatim, unchanged, with the spec citations
# kept. The other eight regions' tables were NOT individually confirmed
# by either spec (v7 spec says so explicitly for each) and were verified
# by THIS implementing pass, 2026-09-10, by reading game/map_data/
# geographical_regions/geographical_region.txt and game/common/
# landed_titles/00_landed_titles.txt directly -- see each region's own
# header below for exactly what was checked and what, if anything, the
# spec's own guess turned out to need correcting.
# =====================================================================
